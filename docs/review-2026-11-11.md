# Project review, 11 November 2026

A review of the whole repository at `79c3c9a` (branch `feat/b7-operations`, before run B.7 is built): server, sidecar, web client, deployment, CI and documentation.

## How this review was done, and what it did not cover

The review was done by reading, in one session, without running the build or any test.

- **Read in full:** `docs/architecture.md`, the run cards' statuses and the B.5, B.6 and B.7 cards, `Program.cs`, everything under `Auth/`, `Permissions/`, `Security/`, the sync hub and its connection, the update store, the compactor and its worker, the attachment endpoints and file rules, the page endpoints, search, the import's upload endpoint, `api.ts`, `AppShell.vue`, `PageView.vue`, the router, `style.css`, the paste sanitiser and link rules, the service worker, the manifest, the `Dockerfile`, the compose file and the CI job list.
- **Checked by pattern across all source:** unsafe HTML, inline styles, arbitrary Tailwind values, default-palette colours, type escapes, blocking calls, raw SQL, skipped tests, suppressed warnings, storage use, and translation parity.
- **Not read:** the import pipeline's internals (`ImportRunner` and the converters, about 5,000 lines), the export writers, `TreeService`'s internals, the sidecar's source, the internals of `syncClient.ts` and the offline store, the editor extensions, the migrations, and the tests themselves. Findings in those areas are limited to their size and shape.

Findings that rest on code I did not read to the end say so.

## Summary

The code is in better shape than most projects at this stage. Authorisation is deny-by-default and enforced by a filter on every route, the CSP is strict with no exceptions in the app's own pages, the sidecar and the container are locked down, and there are about 77,000 lines of tests for about 30,000 lines of source. I found no vulnerability that an outsider can use today.

What needs attention, in order:

1. **Version history is half merged** and nothing in the roadmap said so (now fixed in the plan). Do not rely on it.
2. **Four pieces of work had no run at all:** changing your own password, a limit on page size from live edits, deleting pages and unused files for good, and making a role change reach open sync sockets. They are now in the roadmap.
3. **Three things become real risks the day a second person joins** (phase 2): the role cached per subscription, updates that are stored without being checked, and attachments read through the page they were uploaded to.
4. **`docs/architecture.md` is too large to load cheaply.** It is about 35,000 tokens, and every run reads it. This costs more of the Pro budget than any code problem here.
5. **Interface duplication:** there is no button component, and the same class strings and the same online/offline logic are repeated across files.

## 2. Security

No finding here can be used by someone without an account. The first three matter from phase 2.

| # | Severity | Finding | Where | Suggested action |
| --- | --- | --- | --- | --- |
| 2.1 | High in phase 2 | **A role is read once per subscription.** `Subscription(room, CanEdit)` is set when a page is subscribed and never read again. A member who is removed, or an editor made a viewer, keeps reading and writing every page they have open until their socket closes. The five-minute session check looks at the session only. | [SyncHub.cs:304-315](../server/src/Inkpact.Api/Sync/SyncHub.cs#L304-L315) | Added to run 2.2: on a role change, re-check that user's subscriptions, the way `SessionEvents` already closes sockets on logout. |
| 2.2 | Medium in phase 2 | **An update is stored without being checked.** The hub appends any bytes an editor sends, and `POST /pages` with `content` stores a first update the same way. Bytes that are not a Yjs update make the page fail compaction for good (the worker backs off up to 24 hours, so the log stays quiet), and every client that opens the page is sent them. Nothing removes a bad update. I did not check how the client behaves when it is sent one. | [SyncHub.cs:266-271](../server/src/Inkpact.Api/Sync/SyncHub.cs#L266-L271), [PageEndpoints.cs](../server/src/Inkpact.Api/Pages/PageEndpoints.cs) | Today only you can do this to your own pages. Before sharing: when compaction refuses an update, move that row to the archive with a flag and tell the administrator, so one bad row does not poison a shared page. Checking every update in the sidecar on the hot path is not worth its cost. |
| 2.3 | Medium | **No limit on what live edits make of a page.** The import keeps a page under 8 MiB, but the hub accepts updates without looking at the page's total. A page whose stored bytes pass `Sync:MaxQueuedBytes` (16 MiB) cannot be sent to anyone: the reply overflows the queue and the connection is dropped, for every page on that socket. Nine pastes of just under 2 MiB reach it. I found no server-side check (`MaxPageBytes` is used only by the import and the copy endpoint). | [SyncConnection.cs](../server/src/Inkpact.Api/Sync/SyncConnection.cs), [SyncOptions.cs](../server/src/Inkpact.Api/Sync/SyncOptions.cs) | Run B.10 (added). |
| 2.4 | Low | **The audit log keeps whatever was typed in the email field** of a failed login. People do type a password there by mistake. B.7's rule keeps typed addresses out of the *log*, but the table still has them, readable by run 2.9's admin page. | [AuthEndpoints.cs:170](../server/src/Inkpact.Api/Auth/AuthEndpoints.cs#L170) | Store the typed value only when it parses as an email address (`NormalizeEmail` is not null). |
| 2.5 | Low | **The login limit per address counts the proxy when there are two proxies.** `ForwardedHeaders` trusts one hop. Behind a tunnel in front of Traefik, every visitor has the tunnel's address and shares ten attempts a minute. | [AuthenticationSetup.cs:98-116](../server/src/Inkpact.Api/Auth/AuthenticationSetup.cs#L98-L116) | Add `Network:ForwardLimit` and a paragraph in the self-hosting guide. |
| 2.6 | Low | **The Postgres image is not pinned by digest** in the compose file, while every image in the `Dockerfile` is. The PGDG signing key is downloaded at build time without a fingerprint check. | [docker-compose.yml](../deploy/docker-compose.yml), [Dockerfile](../Dockerfile) | Pin the digest (Dependabot's docker ecosystem can move it). Check the key's fingerprint in the same `RUN`. |
| 2.7 | Note | **A database password with `;` or `'` breaks the connection string** the compose file builds, with an unhelpful error. | [docker-compose.yml](../deploy/docker-compose.yml) | One line in `.env.example`: letters and digits only. |
| 2.8 | Note | **Four templates bind `:style`** for menu positions. Vue sets these through the style object, which the CSP allows, and the Playwright CSP check passes; but `CLAUDE.md` forbids inline styles without naming this exception. | `LinkMenu.vue`, `PageLinkMenu.vue`, `SlashMenu.vue`, `TableMenu.vue` | Name the exception in `CLAUDE.md` (position bindings only), so a later run does not copy the pattern for colours or sizes. |

**What is done well, and should stay as it is:** the role filter with 404 for strangers and 403 for too low a role; the Origin check and the account-bound subprotocol on the WebSocket; constant-time handling of unknown addresses and locked logins; the `__Host-` cookie with the plain-HTTP fallback; attachment types decided from the file's bytes, with a sandboxing CSP on every user file; the sidecar's empty environment and permission model; the read-only, capability-free container; and actions and images pinned by hash.

## 7. Tests

You asked to leave most testing for later, so this is short. The automated suite is strong, and nothing here asks for more of it now.

- No test is skipped to get a green run. The 83 Playwright skips are per-device (`test.skip` on the project name), each with a reason.
- A pull request runs lint, types, unit tests and the build; the server's integration tests and Playwright run locally and on main. This is a deliberate trade for the free plan, and the cost is that main can go red after a merge. Keep `pnpm check` before the last push.
- The new runs B.9, B.10 and 2.2's addition are on critical paths (auth, sync, permissions), so by the project's own rule their tests come with them, not later.
- For the manual test pass (run 2.10b), add: the dark start-up of the installed app (5.5), the Dutch read-through (5.8), and login through two proxies (2.5).

# Links between notes

Detail for the import, the backlinks and the editor's link menus, from [architecture.md](../architecture.md). Moved here from the plan (review 2026-11-11, finding 6.1); nothing changed.

**Links between notes** (run 1.16c). A page made from a Joplin note or notebook gets an id worked out from the workspace and the Joplin id (a version 8 UUID from the SHA-256 of the workspace id, `joplin` and the Joplin id; `PageIds`), unless an earlier import already made it, which keeps the id it has. So a `:/id` link (Markdown, or `<a href>` in HTML) can become a link mark to `/p/<pageId>` before the note it points to is imported, and still points to the right page when a later import makes it. A link to a note that this import does not make (not in the export, or skipped: encrypted, in Joplin's trash, too large) points to the page that note will have, and the report says `note_link_missing`. An id the export does not have at all cannot be told from a file deleted in Joplin, whose link then never works; the message says so. A `:/id` of a tag, or of a file of the export that could not be stored, keeps its text (`resource_missing`). Version 8 ids are the import's: the API refuses one chosen by a client, and should a page have one anyway, the import gives the new page an id of its own (its links then do not reach it, but nothing is lost). Hash-based ids are not time-ordered, so pages made by an import go into the index in random order; at the size of a notes library that costs little, and the links need them. The editor allows exactly `/p/<lowercase uuid>` as a path inside the app (`links.ts`; no query, fragment or extra path), so a page link survives pasting and rendering, and a path that someone typed into a Joplin note is still removed as any relative address. Opening a link: while a page is edited, a click or tap places the cursor in the link like in any text, and a small menu under the link opens it; Ctrl or Cmd with the click opens it at once, in a new tab. On a page that cannot be edited a click opens it. A page of this app (also its full address on this origin, as a copied link has it) opens through the router in the same tab, a mail address in the mail program, anything else in a new tab. Version 2 of the converter (`ImportOptions.ConverterVersion`) makes these links, so the next import converts every page of version 1 again that nobody has changed here (counted `reconverted`); one that was changed here keeps its content and its text links.

**Backlinks and broken links** (run B.1a). The pages whose content links to a page are listed under it ("Linked from"). The server finds the links, since content is opaque to it: the sidecar's compaction answer lists the pages that the `link` marks of the merged content point to (`/p/<uuid>` exactly, with no query, fragment or further path: what the editor and the import write; sorted, once each), and the compactor makes the page's rows in `page_links` those, in its transaction. A page's links are therefore as fresh as its search text: within about two minutes of its last edit (a compaction of a page with more live updates than one batch indexes as far as it has got). A page that links to itself has no row. The pages that exist from before the index are indexed by a job at start-up (`LinkBackfill`): every page whose `links_indexed` is below the version of the extraction and that has no live updates (a compacted page nobody edits, which no compaction would ever reach; a page with live updates is the compactor's, which indexes it in its batches). In batches, each page in one transaction under the compactor's advisory lock for it (a page being compacted is left to the compactor), its snapshot alone given to the sidecar's links-only operation, which encodes and reads back nothing. A sidecar that is down ends the pass, and a page that finds it down three times (it cannot be read in time, or it takes the sidecar down) is left until the next start, so it cannot keep taking everybody's sync down; a page that does not decode, or meets any other error, is logged and left. The job never stops the host, does nothing when the sidecar is off, and stops until the next start after twenty passes that met something in the way. A change to what counts as a link raises the version, which indexes everything again at the next start. `GET /api/pages/{id}/backlinks` (viewer role on the page) answers from the index with the pages that are live (not in the trash, nor below one: `live_pages`, as the tree and search) and that the person may view, each through the permission service's page role (where shares of a page arrive in run 2.2), by title, with their parent's title, at most 200 and a flag when there are more. A link to a page that is in the trash or cannot be found is struck through in the editor, with the reason in its title and for a screen reader (a decoration that follows the tree this tab has, never written into the content): it is whole again the moment the page is restored, and a link to a page of another workspace that the person cannot see looks like one to a page that does not exist.

**Making links** (run B.1b). Typing `[[` at the start of a line or after a space opens a menu of the live pages of the workspace whose title contains what is typed after it: case and accents ignored, titles that start with it first, at most 8, never the page the link is made on, and the page each is in named when two share a title. It reads the tree this tab has, so it works offline and finds a page made a moment ago. Enter or a click replaces `[[` and what was typed with the page's title as text with a link to `/p/<id>`, and what is typed next is not part of the link (TipTap's link mark continues at its end while autolink is on, so it is switched off after a link that was just made). Escape closes the menu and keeps the text; `]` closes it as well. "Link to page" in the slash menu and the Link button of the phone's toolbar (with nothing selected) type `[[`, so there is one way in. **Ctrl+K (Cmd+K) means two things:** with text selected in the editor, or the caret in a link, it opens a picker (a dialog, as search is) that puts a link on the selection or changes the link; anywhere else it opens search. The app shell listens for the key before any element does, so it asks the editor first (`linkShortcutRegistry.ts`, with no imports, so that the editor stays out of the main bundle), and the editor reads the selection as the browser has it, since its own follows one event later. The picker lists the same pages; what is typed is also offered first as a link to that address when it is one the editor allows (`http`, `https`, `mailto`, or a page of this app, which becomes `/p/<id>`). The menu under a link has "Open", "Change link" and "Remove link". A link is changed or removed as a whole, also when only a part of it is selected, so it is never split in two; nothing that makes a link is offered in code (a code block or inline code), where a link cannot go. The picker keeps its text as Yjs relative positions while it is open, as an upload does, so a change from another client meanwhile does not move the link onto other text. A link this person makes to a page of this app, by paste, by a typed address that becomes a link, or by the picker, is stored as `/p/<id>` whichever way it was written (the address bar and the clipboard have the full address, which the index of links does not count): a plugin looks only at what a local transaction changed, and never at a change that came from another client through Yjs, which it would otherwise rewrite on every client at once. A link that was pasted in full before this stays as it was: it opens as a page, but has no backlink until it is made again.

# Export

Detail for "Export" in [architecture.md](../architecture.md). Moved here from the plan (review 2026-11-11, finding 6.1); nothing changed.

- **Layout.** A page is `Title.md`; the pages under it are in the folder `Title/` beside it, in tree order. Attachments are in `_attachments/` at the top, one copy per content (SHA-256), each under its own file name. `README.md` at the top (the workspace's name in it escaped, so its Markdown or HTML shows as written) says what the export is and how it is laid out, in the language the client sends (`?lang=`): its words are `export.readme.*` in `en.json` and `nl.json`, built into the server as the import's allow-list is, so the server writes no language of its own (English is the fallback).
- **Order** is the tree's own (`Pages/TreeOrder`, which the tree endpoint uses too): parents first, siblings by key as bytes, then by id; walked without recursion.
- **Names** are valid on Windows, macOS and Linux and the same for the same tree: the characters `/ \ : * ? " < > |` and control characters become a dash, a leading dot and a trailing dot or space go, Windows' reserved names (`CON`, `NUL`, `COM1` and the like, also with an extension) get a `_`, names are in Unicode form C and cut at 100 characters without splitting a character, and an empty title is `Untitled`. Names that differ only in case or Unicode form count as one (Windows and macOS compare them so), a page takes both its file and its folder name (a page called `X.md` does not take the file of a page called `X`), and the second of two is `Name (2)`, in tree order. `README.md` and `_attachments` are reserved at the top.
- **Pages** have YAML front matter with what is on the page row and not in the document: `title`, `id`, `created`, `updated` (UTC), `tags` when there are any, and for a to-do `todo: true`, `completed` and `due` when set. Text is a YAML double-quoted string that escapes only the backslash, the quote and what YAML cannot print (control characters, U+2028 and U+2029), so no title breaks out of its line and emoji and every other character are written as themselves. The title is not repeated as a heading. The body is the writer's Markdown (run 1.18a).
- **Links** between pages, pictures and files are relative paths, percent-encoded wherever a reader could misread a character (letters and digits of any script stay as they are), so they keep working when the folder moves. A link to a page that is not in the export (in the trash, say) stays `/p/<id>`; an id that is no attachment of this workspace stays `attachment:<id>` and its file is not exported: an id named in a page's content cannot make the export carry a file from another workspace. Files on pages in the trash may be used by pages that are exported (whoever reads the workspace may read its files).
- **Left out:** the trash and what is below it, Yjs state, history, accounts. Files only appear when a page uses them: a file removed from a page, or an earlier version kept by a re-import, is not in the zip.
- **Streaming.** The zip is written into the response as it is made (`ZipArchive` over `ResponseZipStream`, which never writes synchronously, since Kestrel refuses that, and gathers small writes into 64 KB sends), with no temporary file and nothing kept on the server. The response is opened, its headers set and its audit line written, with the first send. Pages are read one at a time and files copied in chunks, so memory stays the size of a page and a chunk: 5,000 pages and 100 MB of files take 13 seconds and 23 MB of managed memory (files read twice, see below) on the development laptop. Markdown is compressed, files are stored as they are. Entries are dated with the page's last change (the clock of its UTC time; a zip has no time zone). No background job: a dropped download is started again.
- **A zip is whole or it fails.** While nothing has been sent (the first 64 KB), a sidecar that is down is `503 export_unavailable` and no zip. A failure after that cuts the connection and never writes the zip's index, so the download fails in the browser and no tool opens what arrived. A file that cannot be read as stored, and a page whose stored bytes are no page (the sidecar refuses them), do not stop the export: the file is left out, the page is there with its front matter only, both are listed in the README and logged. To know a file can be read before its entry is begun (an entry cannot be taken back), each file is read through once and its SHA-256 checked first: the store does not have it, it cannot be opened or read (permissions, a bad disk), or its bytes are not the ones its hash names, and it is left out rather than failing every export of the library at that file. Content the editor's schema does not have is counted and logged once per export.
- **Known limit:** Windows Explorer refuses paths over 260 characters, which a few levels of 100-character titles reach. The names are not shortened further; the zip is fine in other tools and in Explorer for ordinary titles.

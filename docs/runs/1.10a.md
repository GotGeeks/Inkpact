# Run 1.10a: Yjs sidecar and diff on subscribe

**Model:** O·high → S·high (planned on Opus 5.5, built on Sonnet)

## Goal

A small Node process running Yjs becomes the server's only decoder of Yjs updates. The server starts it as a supervised child process, talks to it over stdin and stdout with binary frames, and restarts it when it dies or hangs. The sync hub uses it to answer a subscribe with the diff the client is missing plus the server's state vector, and falls back to the stored log when the sidecar is unavailable. The codec operations that compaction (run 1.10b) needs are built and tested here as well, so 1.10b only writes server code.

## Done when

- `dotnet test server` starts the real sidecar and the codec contract tests pass through it.
- A subscribe is answered with one diff update and the server's state vector; the client's state plus that diff equals the stored page.
- With the sidecar stopped, crashed, hung or given an undecodable log, a subscribe still gets the stored log, and the sidecar comes back on its own.
- The app starts and syncs (in log mode) when Node is missing, and says so in the log.
- CI runs the sidecar's own tests, type check and Prettier, and has Node for the server tests.

## Decisions (confirmed)

1. **Run 1.10 is split** into 1.10a (this card) and 1.10b (compaction), because as one run it would touch about 35 files. The roadmap row says so.
2. **`yjs` is added** as the sidecar's only runtime dependency, at the version the web client will use in 1.11. `typescript`, `vitest` and `@types/node` are reused as dev dependencies at the versions `web/` already has. No NuGet package is needed.
3. **The text extract is schema-free:** a walk over the Yjs XML tree, not TipTap's schema. It needs only `yjs`, works for any document and does not break when 1.11 adds editor nodes. It is not exactly ProseMirror's `textBetween`, which search does not need.

## Design

### The sidecar package (`server/sidecar/`)

- A pnpm workspace package named `sidecar`, added to `pnpm-workspace.yaml`. `type: module`, `engines.node >= 24`, private, AGPL-3.0-only.
- **No build step.** Node 24 runs the TypeScript directly through type stripping, so the code uses only erasable syntax (no enums, no parameter properties, no namespaces). `tsconfig.json`: `noEmit`, `erasableSyntaxOnly`, `allowImportingTsExtensions`, `verbatimModuleSyntax`, `module: nodenext`, strict. Imports carry the `.ts` extension.
- Scripts: `test` (Vitest), `typecheck` (`tsc --noEmit`), `lint` (`prettier --check .`).
- Files:
  - `src/main.ts`: reads request frames from stdin, runs them one at a time, writes response frames to stdout. Logs go to stderr only, since stdout carries the protocol. Exits when stdin ends, so the sidecar never outlives a server that died.
  - `src/framing.ts`: a frame reader that copes with frames split across chunks or packed several to a chunk, and the encoder.
  - `src/ops.ts`: the operations.
  - `src/text.ts`: the text extract.
- **Every input update is applied in its own `Y.applyUpdate` on a fresh `Y.Doc`, never in one `Y.transact`** (the run 0.5 finding). Comment this where it happens. Nothing uses `Y.mergeUpdates`: it cannot drop deleted content (consequence 3).

### Protocol

All integers are little-endian `u32`. Requests are answered in order, but the server matches by id anyway.

```
request:  [length][id][op: u8][count][count × ([length][bytes])]
response: [length][id][status: u8, 0 = ok, 1 = error][count][count × ([length][bytes])]
```

`length` at the start counts the bytes after it. An error response has one part, the message in UTF-8. A frame over 256 MiB is a broken stream: the sidecar writes nothing more and exits, and the server restarts it.

| Op | Parts in | Parts out |
| --- | --- | --- |
| 0 `ping` | none | protocol version (`1`, as text), Yjs version |
| 1 `diff` | client state vector, then the page's updates in order | the update the client is missing (`Y.encodeStateAsUpdate(doc, sv)`), the server's state vector |
| 2 `compact` | the inputs (snapshot first, if any, then the updates) | state (`Y.encodeStateAsUpdate`), its state vector, the fingerprint of the inputs replayed, the fingerprint of the state decoded on its own fresh doc, plain text |
| 3 `fingerprint` | updates in order | fingerprint of their replay |

- An empty client state vector means "I have nothing" and gets the full state.
- **Fingerprint:** `Y.encodeSnapshot(Y.snapshot(doc))`, the state vector plus the delete set, both in sorted order. Equal fingerprints mean the same CRDT document whatever its content or schema (consequence 4).
- `compact` returns both fingerprints and the server compares them. Comparing the state decoded on its own doc with the replay catches an encoding that does not round-trip.
- An operation that throws (an undecodable update, a broken state vector) answers with an error and the sidecar keeps serving.

### Text extract (`text.ts`)

- Reads the `XmlFragment` named `default`, the field TipTap's collaboration extension uses. A document without one, or with other root types only, has the text `""`.
- `XmlText`: its string inserts, in order. Embeds and attributes (link targets, image sources) are skipped.
- `XmlElement`: a block. Its text is on its own line, so a new line starts before and after it. An element without children (a hard break, an image) becomes a line break.
- Afterwards trailing spaces are trimmed from every line, more than one empty line in a row becomes one, and the whole is trimmed.
- Unit tests for: paragraphs, headings, nested lists, a table, a code block, a hard break, marks inside a word (`he**ll**o` stays `hello`), emoji and a split surrogate pair, an empty document, a document without `default`.

### Server side (`server/src/Inkpact.Api/Crdt/`)

- **`IYjsCodec`**, so the hub and later the compactor can be tested with NSubstitute:
  - `DiffAsync(ReadOnlyMemory<byte> stateVector, IReadOnlyList<byte[]> updates, ct) → YjsDiff(byte[] Update, byte[] StateVector)`
  - `CompactAsync(IReadOnlyList<byte[]> inputs, ct) → YjsCompaction(byte[] State, byte[] StateVector, byte[] ReplayFingerprint, byte[] StateFingerprint, string Text)`
  - `FingerprintAsync(IReadOnlyList<byte[]> updates, ct) → byte[]`
  - Two exceptions: `YjsUnavailableException` (not running, died during the request, timed out) and `YjsRejectedException` (the sidecar answered with an error: the input does not decode).
- **`YjsSidecar`**: implements `IYjsCodec` and is a hosted service that supervises the process.
  - **Start:** in the background, so the app never waits for it. A `ping` checks protocol version 1 and logs the Yjs version. Until it is answered, calls fail with `YjsUnavailableException`.
  - **Reading:** one loop reads response frames from stdout and completes the waiting call by id. stderr goes to the log as warnings.
  - **Writing:** one frame at a time, under a lock. Calls may be in flight together; the sidecar answers them in order.
  - **Timeouts:** every call has one: `DiffTimeout` for `diff`, `RequestTimeout` for the others. A call that times out kills the process: Node runs one request at a time, so a stuck request blocks all the others.
  - **Restart:** when the process exits or is killed, all waiting calls fail with `YjsUnavailableException`, the last stderr lines are logged as an error, and it restarts after a backoff: 1 s, doubling up to 1 min, back to 1 s after a minute of healthy running.
  - **Stop:** close stdin, wait up to 5 s, then kill the process tree.
  - **Node missing or the script missing:** an error in the log, then the same backoff. The app keeps running in log mode.
- **Starting the process safely:**
  - `node` is resolved to a full path once, from `Sidecar:NodePath` or `PATH`.
  - The child starts with an **empty environment** plus what Node needs (`NODE_ENV=production`; on Windows also `SystemRoot`). By default it would inherit the server's environment, which in Docker holds the connection string.
  - Arguments: `--max-old-space-size=<MaxHeapMb>`, `--disallow-code-generation-from-strings`, and the script.
  - Try Node's permission model (`--permission --allow-fs-read=<sidecar directory>`), so a Yjs bug cannot read the disk. Keep it only if module loading works with it on Linux and Windows. Write down what happened either way.
  - The sidecar has no network port: stdin and stdout only.
- **`SidecarOptions`** (section `Sidecar:`):
  - `NodePath` (empty: from `PATH`).
  - `ScriptPath`, relative to the content root. The default in `appsettings.json` is the published location (`sidecar/src/main.ts`, for 1.13); `appsettings.Development.json` points at `../../sidecar/src/main.ts`.
  - `MaxHeapMb` 512, `DiffTimeout` 2 s, `RequestTimeout` 60 s.
  - `Enabled` true. Tests that need no Yjs turn it off; it then behaves exactly like a sidecar that cannot start.
- **Wiring:** `AddYjsSidecar(configuration)` in `Program.cs`, as one singleton that serves as both `IYjsCodec` and the hosted service.

### Sync frame and subscribe

- **The Sync frame gains the server's state vector:** `[type][pageId][varUint8Array stateVector][varuint count][count × varUint8Array update]`.
  - **Diff mode:** the state vector is the server's and there is one update, the diff.
  - **Log mode:** the state vector is empty, the updates are the stored log, and the client works out what the server lacks, as today.
  - Why the frame changes after all: with only a diff, the client cannot know the server's state vector, so it cannot send what the server is missing. Run 1.09's card said the protocol would stay the same; that holds for the subscribe, not for the reply. No client exists yet (1.11), so the change is free now.
  - Update the comment in `Frame.cs` and "Sync flow" step 2 in the architecture in the same PR.
- **`SubscribeAsync`**, still under the page lock:
  - Load the log, then `DiffAsync(subscribe payload, log)` with `DiffTimeout`.
  - On `YjsUnavailableException`: log mode, logged at debug, since it is expected while the sidecar restarts.
  - On `YjsRejectedException`: log mode, logged as a warning with the page id. It means the log holds something Yjs cannot decode; 1.10b will see it again.
  - Holding the lock during the call is deliberate: it keeps "each update exactly once, in the sync or live". `DiffTimeout` bounds the wait.
- The hub still never decodes an update on the write path. Appends stay opaque and do not depend on the sidecar, as CLAUDE.md requires.

## Handoff

### As built

- **`server/sidecar/`** (pnpm package `sidecar`, Node 24 runs the TypeScript, no build): `framing.ts` (frame reader and encoder), `ops.ts` (ping, diff, compact, fingerprint), `text.ts` (the schema-free text extract, an iterative walk so a deeply nested page cannot exhaust the stack), `main.ts` (one request at a time; exits when stdin ends, or with code 1 after a frame over 256 MiB). `yjs` 13.6.33 is the only runtime dependency (with its own `lib0` and `isomorphic.js`, none with install scripts). The dev dependencies are the web client's versions of `typescript`, `vitest`, `@types/node` and `prettier` (the lint script needs it; same version, already in the lockfile).
- **`server/src/Inkpact.Api/Crdt/`:** `IYjsCodec` with its two exceptions, `SidecarOptions`, `SidecarSession` (one process and the conversation with it: write lock, pending calls by id, read loop, stderr to the log), `YjsSidecar` (the hosted service that starts, restarts and stops sessions, and the codec), `SidecarPermissions` and `AddYjsSidecar`.
- **Hub:** the Sync frame is `[type][pageId][stateVector][count][updates]`. A page with an empty log is answered without asking the sidecar (empty state vector, no updates). Otherwise `DiffAsync` runs under the page lock; `YjsUnavailableException` goes to log mode and is logged at debug level, `YjsRejectedException` at warning level with the page id. Frame.cs and "Sync flow" step 2 are updated, and so are "Server CRDT handling", the security list and the CI list in the architecture.
- **Permission model kept.** Tried first on its own (`--permission --allow-fs-read=<sidecar folder>`), module loading **fails** on both Windows and Linux, because pnpm's `node_modules/yjs` is a link (a junction on Windows, a symlink on Linux) into `<repo>/node_modules/.pnpm`, outside the folder. With the store allowed as well it works on both (Linux checked in a `node:24` container with a Linux install from the lockfile). It blocks reading other files, writing and starting processes (probed on both systems, and by a test through the supervisor). `SidecarPermissions` finds the package folder and follows the links in its `node_modules` to the `.pnpm` store; a deployed sidecar with its packages inside needs nothing more.
- **CI:** the server job runs `setup-web` first; the web job runs the sidecar's lint, typecheck and tests. Playwright's server gets `Sidecar__ScriptPath` (its content root is the build output, with no sidecar next to it). `CLAUDE.md` and `CONTRIBUTING.md` say to run `pnpm install` before `dotnet test`.
- **Fixtures:** the spike's, in `Fixtures/yjs/` (README with provenance), plus `non-tiptap.json` and the golden fingerprints of the one-transaction repro, written by `server/sidecar/scripts/yjs-fixtures.ts`. Five stand-in sidecars in `Fixtures/sidecars/` (silent, deaf, crashing, environment, permission probe) for the supervision tests.

### Where it differs from the card

1. **A timeout kills the process only when the late request is the oldest one waiting.** The card says any timeout kills. A diff (2 s) queued behind a 30 s compaction would then kill the compaction. A request behind a slower one is only abandoned; the one in front has its own timeout. The oldest request is the one Node is working on, which is the stuck one the kill is for. Tested both ways.
2. **The hub has a backstop of twice `DiffTimeout`** around `DiffAsync`, for a codec that ignores its own timeout. The real sidecar always times out first. This is what the card's "a codec that hangs" test needs; a real hung process (a stand-in that never answers) is tested as well.
3. **The 1.09 hub tests run with `Sidecar:Enabled=false`** (the factory default), not with an NSubstitute codec that throws. Disabled behaves exactly like a sidecar that cannot start, so their counts are unchanged. Tests that want the real thing pass `sidecar: true`; those that want a failing codec pass `codec:`.
4. **The text of the TipTap fixtures is compared line by line** with ProseMirror's (their `expectedText`), ignoring empty lines and trailing spaces, since the walk is schema-free by decision 3. They agree on all four random fixtures.

### Found while building

- **Prettier finds its configuration per package.** The sidecar needed its own `.prettierrc.json` (a copy of the web's); without it `--write` reformatted everything with the defaults.
- **Building a deep Yjs document one transaction per level is quadratic** (20 s for 20,000 levels); one transaction takes 14 ms. Only the test needs that.
- **Yjs writes the clients of a state vector in descending order;** the fixtures list them ascending. Compared sorted.
- **pnpm uses junctions on Windows,** which need no privilege where symbolic links do; `ResolveLinkTarget` follows both. The permissions test makes a junction on Windows.
- **Node 24.22 prints nothing to stderr** for type stripping or for the permission model, so every stderr line is worth a warning in the log.

### Not covered by a test

- The C# supervisor on Linux: CI runs it, this machine is Windows. The Node side was checked on Linux in a container.
- The restart backoff beyond the first second (doubling, the reset after a minute): it uses real time, and a test would take minutes. The first restart is covered.
- That Node needs `SystemRoot` on Windows, which the card asked to pass: the sidecar was not tried without it.

### For 1.10b (compaction)

- `CompactAsync(inputs)` takes the snapshot first, then the updates. It returns the state, its state vector, **both** fingerprints (compare them, and compare the replay one with a full replay for verification, via `FingerprintAsync`) and the text. `YjsRejectedException` means an input does not decode: back off from that page and log it, as the hub does. `YjsUnavailableException` means try later.
- **The sidecar does one request at a time.** While a compaction runs (up to `RequestTimeout`, 60 s) a subscribe to any page waits behind it, gives up after `DiffTimeout` and gets the log. Keep each compaction call short (one page at a time, a sampled full-history check) and say so in the card if it hurts; a second process would be the fix.
- `LoadAsync` still returns the updates only. When the snapshot joins them, the list passed to `DiffAsync` is `[snapshot, ...updates]`, and in log mode the snapshot goes out as the first update, which Yjs accepts.
- A page with no updates is answered without the sidecar; keep that when the snapshot exists (an empty list of inputs, not an empty page).

### For 1.11 (editor and client)

- The Sync frame is `[type][pageId][varUint8Array stateVector][varuint count][updates]`. **Diff mode** (state vector not empty): one update; apply it, then send the server `Y.encodeStateAsUpdate(doc, serverStateVector)`. **Log mode** (state vector empty): the stored updates; apply them, load them into a scratch document for the server's state vector, then send what the page has beyond that. A client that sends its whole state is also correct, only bigger.
- The server's state vector is the only reliable way to know what it lacks; do not keep one across a reconnect.

### For 1.13 (Docker image)

- The image needs Node 24, and a `sidecar/` folder next to the app with `src/` and its production `node_modules` (`pnpm deploy --filter sidecar --prod` puts the store inside the folder, so the permission model needs no extra path). Debian-based, as decided in the spike. The sidecar writes nothing, so a read-only root filesystem is fine.

# Run 1.04: security headers, strict CSP, SPA served by ASP.NET Core, Playwright harness

**Model:** O·high → S·med (planned on Opus 5.5, built on Sonnet)

## Goal

The production web bundle is served by the ASP.NET Core app with a strict Content Security Policy and the other security headers from the baseline. A Playwright suite on a desktop and a phone viewport runs against that real server and fails on any CSP violation.

## Inputs

- `docs/architecture.md`: "Security from day one" (strict CSP, other security headers), "CI/CD" (end-to-end on every PR), "Quality standards" (Playwright on desktop and phone).
- GarageStack's `frontend/e2e/fixtures.ts` and `playwright.config.ts`: the violation collector, and the plain-HTTP project that caught `upgrade-insecure-requests` blanking LAN installs.

## Done when

- `GET /` from the server returns the built SPA with the exact CSP below, and every other response (API, 404, static assets, errors) carries the security headers.
- Deep links (`/some/page`) return `index.html`; unknown `/api/...` paths return a JSON 404, never `index.html`; a missing `/assets/x.js` returns 404.
- `pnpm --filter web e2e` passes on the desktop, phone, iPhone and plain-HTTP projects, and a self-test proves the suite fails when a violation happens.
- CI runs the suite on every PR as a new required check, `e2e`.

## Design

### Headers (`SecurityHeadersMiddleware`, first in the pipeline, set in `OnStarting` so 404s and errors get them too)

```text
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' blob:;
  font-src 'self'; connect-src 'self'; worker-src 'self'; manifest-src 'self'; object-src 'none';
  base-uri 'none'; form-action 'self'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), serial=(), bluetooth=(),
  magnetometer=(), gyroscope=(), accelerometer=(), browsing-topics=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
X-Frame-Options: DENY
```

- **No `'unsafe-inline'`, `'unsafe-eval'`, nonces or hashes.** The built `index.html` has only external `<script type="module" src>` and `<link>` tags. Vue's `:style` bindings go through the CSSOM, which `style-src` does not block; `style="..."` attributes in templates stay forbidden by the project rules.
- **No `upgrade-insecure-requests`.** It blanks every page on a plain-HTTP LAN install (GarageStack hit this). HSTS stays in Traefik, as the architecture says.
- **`connect-src 'self'` covers the app's own WebSocket.** CSP Level 3 matches `ws:` and `wss:` to the same host under `'self'` in Chrome, Firefox and Safari. No host name is built from the request. The first WebSocket arrives in 1.09, and the phone project proves it then.
- **`img-src blob:`** is for pasted and uploaded images shown before upload (1.14). No `data:`.
- **The `Server` header is removed** (`AddServerHeader = false`).
- **Not in this run:**
  - `report-to` and a report endpoint: an anonymous write endpoint wants rate limiting (1.06).
  - Trusted Types (`require-trusted-types-for 'script'`): it needs checking against ProseMirror first (1.11). Recorded as an open question.

### Serving the SPA

- The Vite build goes to `web/dist`. The server serves the web root, which is `wwwroot` by default and set with `ASPNETCORE_WEBROOT` for local and e2e runs. The Docker image in 1.13 copies `dist` into `wwwroot`. There is no MSBuild copy step.
- Routing order:
  1. `UseStaticFiles`, with `Cache-Control: public, max-age=31536000, immutable` for `/assets/*` (hashed names) and `no-cache` for everything else.
  2. API endpoints, plus `app.MapFallback("/api/{**path}", ...)`, which returns a JSON 404 `{ "code": "not_found" }`, so unknown API paths never get HTML.
  3. `MapFallbackToFile("index.html")` for everything else that isn't a file. It is anonymous by design, because the shell contains no data.
- `index.html` is sent with `no-cache`.
- If the web root has no `index.html` (an API-only dev run), the fallback answers 404 instead of throwing.

### Vite

- `define`: `__VUE_I18N_LEGACY_API__: false`, `__VUE_I18N_FULL_INSTALL__: false`, `__INTLIFY_PROD_DEVTOOLS__: false`, `__VUE_PROD_DEVTOOLS__: false`.
- vue-i18n 11 compiles messages with its JIT compiler (an AST interpreter, no `new Function`), so the message compiler needs no `unsafe-eval`. The e2e suite proves it. If it doesn't hold, the fallback is precompiling with `@intlify/unplugin-vue-i18n`, which would be a new dependency to ask about.
- `server.proxy` sends `/api` to the ASP.NET dev server, so `pnpm --filter web dev` works against `dotnet run`. The dev server has no CSP (Vite injects `<style>` for HMR). That is exactly why the e2e suite runs against the built bundle.

### Playwright (`web/e2e`, new dev dependency `@playwright/test`)

- **Target: the real server, not Vite.** `webServer` in `playwright.config.ts` runs `pnpm build`, then the Release-built `Inkpact.Api.dll` (built to its own output folder so it never locks a running dev server; a spike 0.3 lesson) with:
  - `ASPNETCORE_ENVIRONMENT=Production` (production headers and error handling);
  - `ASPNETCORE_URLS=http://127.0.0.1:5090`;
  - `ASPNETCORE_WEBROOT=<repo>/web/dist`;
  - `ConnectionStrings__Inkpact` from `E2E_DATABASE`, defaulting to the dev database below;
  - `Database__BackupOnMigrate=false`.
- **Projects:**
  - `desktop`: Desktop Chrome.
  - `phone`: Pixel 7, Chromium.
  - `iphone`: iPhone 15, WebKit. WebKit is where CSP and WebSocket handling differ most from Chromium.
  - `plain-http`: Desktop Chrome on `http://inkpact.test:5090` via `--host-resolver-rules`. `localhost` is a secure origin, so only a non-localhost name shows policies that break plain HTTP.
- **`fixtures.ts`:** a `test` that collects `securitypolicyviolation` events (via `exposeFunction` and `addInitScript`, which CSP does not block) plus `pageerror`, and **fails the test in teardown** if either list is non-empty. Specs never have to remember to assert it. This differs from GarageStack, where each spec asserts.
- **Specs:**
  - `csp.spec.ts`:
    - the document response carries the exact CSP and the other headers;
    - the self-test injects an inline `<script>` and an inline `style` attribute and expects both violations to be caught. It uses a fixture flag to expect violations instead of failing;
    - `eval` is blocked.
  - `smoke.spec.ts`:
    - the app shell renders with the i18n title;
    - the language switch changes the text, by keyboard as well as by tap on the phone project;
    - a deep link serves the app;
    - no horizontal scroll at phone width.
  - `api.spec.ts`: `/api/health` is JSON; `/api/nope` is a JSON 404, not HTML.

### Database for local runs

`deploy/docker-compose.dev.yml` with only `postgres:18-alpine` on `127.0.0.1:5432`, with a named volume. Postgres runs only in Docker; there is no local install. `appsettings.Development.json` already points at port 5432, and the e2e default does too. The full compose file is still 1.13.

### Server tests (xUnit, WebApplicationFactory, a temp web root with a fake `index.html` and an asset)

- Exact header set on `/`, `/api/health`, `/api/nope`, a missing asset, and a 500 from a test-only throwing endpoint.
- No `Server` header.
- Routing: deep link → `index.html` with `no-cache`; `/assets/app-abc123.js` → `immutable`; `/api/nope` → JSON 404 with `code`; `/assets/missing.js` → 404; no `index.html` in the web root → 404.
- The CSP value itself is pinned in one test, so any loosening shows up in review.

### CI

New job `e2e` (timeout 15 min):
- a `postgres:18-alpine` service container;
- `setup-dotnet`, `setup-web`;
- `pnpm exec playwright install --with-deps chromium webkit`, with the browser cache keyed on the Playwright version;
- `pnpm --filter web e2e`;
- the HTML report uploaded on failure.

After merge, add `e2e` to the required checks of the `main` ruleset.

### Docs

- `docs/architecture.md` → "Security from day one": the exact header list, `connect-src 'self'` covering the WebSocket, and no `upgrade-insecure-requests` (LAN HTTP).
- "CI/CD": e2e runs against the built server and bundle until the container exists (1.13).
- `CLAUDE.md` commands: `pnpm --filter web e2e`, and `docker compose -f deploy/docker-compose.dev.yml up -d`.

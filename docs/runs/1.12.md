# Run 1.12: editor polish

**Model:** S·med (planned on Opus 5.5, built on Sonnet). No critical path: the editor's content, sync and sanitising are untouched. `/code-review` at medium.

## Goal

The editor gets what the design promises on top of the plain TipTap of 1.11: a slash menu to insert blocks, Notion-style block handles to move them around, and on a phone a toolbar above the keyboard with undo and redo, since the keyboard's own undo does not work (spike finding 0.6, line 15). The editor stays lazy-loaded, and its size is measured instead of guessed. Everything works with the keyboard alone and under the strict CSP.

## Decisions to propose

Proposed, not yet agreed. Each says what I recommend and what else was weighed.

1. **Split into 1.12a and 1.12b.** Slash menu, toolbar and undo and redo share one list of block commands and are the part a phone needs; handles are desktop only (the design replaces them with the toolbar on touch). As one run it touches about 25 files.
   - **1.12a:** the block command list, the slash menu, the mobile toolbar with undo and redo, the keyboard-aware layout. About 14 files.
   - **1.12b:** block handles with drag and drop, the block menu, keyboard block moves, the table menu, the chunk decision. About 12 files.
   - Weighed: the roadmap order (handles first). The phone is where the known defect is, so it goes first.
2. **One list of block commands** (`editor/blockCommands.ts`): Text, Heading 1 to 3, Bullet list, Numbered list, Checklist, Quote, Code block, Table, Divider. Each has an id, an i18n key, an icon, search words (in both languages) and a command. The slash menu, the toolbar's block picker and 1.12b's "turn into" all read it, so a new block is added once.
   - **Left out although the designs show them:** Callout (not in the plan, not in the schema), Link note (B.1), Image (1.14). The design's "knowledge graph" and similar are ignored as in CLAUDE.md.
3. **The slash menu uses `@tiptap/suggestion`** (new dependency, and its peer `@floating-ui/dom`; ask before adding; both MIT, no install scripts). It does the hard part: the trigger, the query, the range to replace, keyboard hooks. Our part is the list: a Vue component with the combobox and listbox pattern (the editor keeps focus, `aria-activedescendant` names the option, arrow keys, Enter, Escape, Tab closes), positioned with floating-ui through the style object, which the policy allows (no `style` attribute in a template).
   - Weighed: writing the trigger detection ourselves (the edge cases are in the library: IME composition, a slash inside a word or a URL, deleting back past the slash) and Reka's Popover (it is made to be opened by a click, not driven by the text).
   - The trigger is `/` at the start of a line or after a space, so `https://` and `and/or` do not open it. The menu filters as you type, shows "No results" and closes on a space after no match.
4. **The toolbar sits above the keyboard with the visual viewport.** `visualViewport` resize and scroll set a CSS variable (`--keyboard-inset`) on the document element through the style object, and the toolbar is `fixed` at `bottom: var(--keyboard-inset)`. The editor gets the same amount of bottom padding, so the caret is never behind the toolbar (spike line 16).
   - Weighed: the `interactive-widget=resizes-content` viewport hint (Chrome only, iOS ignores it) and `position: sticky` (does not follow the keyboard on iOS). The hint can be added as well, as it costs a meta tag; it is not relied on.
   - Shown only when the editor has focus on a touch device (`pointer: coarse`) or a narrow screen, never on a desktop with a mouse.
5. **Contents of the toolbar**, from the design: Heading, Bold, Italic, Bullet list, Checklist, Code, the slash button, and (new) Undo and Redo at the start. At least 44 px targets, `aria-label` on each, `aria-pressed` for the marks. Image waits for 1.14.
   - Undo and redo run Yjs's undo manager (`editor.commands.undo()` from the collaboration extension, which only undoes this client's own changes), and are disabled when there is nothing to undo.
   - Not a replacement for Gboard's undo, which stays as it is (one character at a time, an Android matter).
6. **Block handles use `@tiptap/extension-drag-handle-vue-3`** (new: it and `@tiptap/extension-drag-handle`, `@tiptap/extension-node-range`; ask). A 6-dot handle at 20% opacity that goes to 100% when the block is hovered or focused, in the 1.75 rem gutter the design reserves; a click opens a block menu (Reka DropdownMenu): Turn into, Duplicate, Delete, Move up, Move down. Dragging moves the block through ProseMirror, so Yjs sees an ordinary edit.
   - **Keyboard and touch have their own way,** since a drag handle is mouse only: `Alt+ArrowUp` and `Alt+ArrowDown` move the block that holds the caret (a small extension), and the slash menu and toolbar do the rest. Handles are hidden on touch.
   - **Proven first:** the handle on the collaboration setup, under the strict CSP, with a table and a list (the library positions its element with floating-ui; if it writes a `style` attribute, stop and say so).
7. **Tables get a small menu** (add and delete a row or column, delete the table), shown while the caret is in one, as a Reka popover on desktop and a row in the toolbar on a phone. Without it a table made from the slash menu cannot be edited past Tab at the last cell. If 1.12b would pass 15 files, this is the part that moves to its own run.
8. **Lazy-loading: measure, then decide.** The editor is in `PageView`'s route chunk (509 kB, about 160 kB gzipped), which is already lazy. This run:
   - makes `PageEditor` an async component, so the page view (title, pill) shows at once and the editor follows, with a placeholder of the editor's height so nothing jumps;
   - records the chunk sizes in the handoff, and adds nothing to CI (size tracking in CI is in the architecture's performance table and belongs with the performance run);
   - splits TipTap into its own chunk only if the measured cost of the async component says it helps. It probably does not: it is the same bytes behind the same route.
9. **Real-device check.** The 0.6 Android checklist is rerun against this editor by you, on the same phone, for: typing, undo and redo buttons, the toolbar above Gboard and SwiftKey, the caret at the bottom of a long page, rotation, the slash menu with the on-screen keyboard. Playwright cannot open a real keyboard, so the tests only cover the layout logic (the visual viewport is faked).

## Design

### Block commands (`editor/blockCommands.ts`, 1.12a)

- `BlockCommand`: `id`, `labelKey`, `descriptionKey`, `icon` (an `AppIcon` name), `keywords` (the i18n keys of its search words, so Dutch finds "lijst"), `run(editor, range?)`. `run` deletes the trigger range first, then sets the block (`setNode`, `toggleBulletList` and so on, or `insertTable({ rows: 3, cols: 3, withHeaderRow: true })`).
- `filterCommands(query, t)`: matches the start of a word in the label or a keyword, case and accent insensitive (`Intl.Collator` with `sensitivity: 'base'`), keeps the list's order for equal matches.
- New icons in `AppIcon.vue`, drawn like the existing ones.

### Slash menu (`editor/SlashMenu.vue`, `slashExtension.ts`, 1.12a)

- `slashExtension.ts` configures `Suggestion` (`char: '/'`, `allowedPrefixes: [' ']`, the start of a line), and hands `items`, `command` and the render hooks to a small controller.
- `SlashMenu.vue` is mounted once beside the editor, not per keystroke: the controller sets its query, its anchor rectangle and its selected index. It is `role="listbox"` inside a combobox the editor root is the owner of (`aria-controls`, `aria-expanded`, `aria-activedescendant`), with a live region that says how many results there are.
- Categorised header (`label-xs`, uppercase) as in the design; `surface-subtle` panel, `border-subtle`, the design's shadow, `rounded-lg`, a maximum height with scrolling, the chosen item in `surface-elevated` and `primary` text. On a phone it opens above the toolbar when there is no room below.
- Disabled while the editor is read-only, and in a code block.

### Mobile toolbar (`editor/EditorToolbar.vue`, `composables/useKeyboardInset.ts`, 1.12a)

- `useKeyboardInset`: listens to `visualViewport` `resize` and `scroll`, writes `--keyboard-inset` (the layout viewport's height minus the visual viewport's height and its offset) on `document.documentElement` through `style.setProperty`, rounds it, and removes it when the editor loses focus. Tested with a fake `visualViewport`.
- `EditorToolbar.vue`: a `role="toolbar"` with roving `tabindex`, `fixed inset-x-0 bottom-[var(--keyboard-inset,0px)]`, `surface-panel`, a top hairline, the buttons above. Buttons keep the editor's focus (`mousedown` and `pointerdown` are prevented, so the keyboard does not close).
- The editor's root gets `scroll-padding-bottom` and the page `padding-bottom` of the toolbar's height while it is shown, so the caret stays in view.
- `useMediaQuery('(pointer: coarse)')` (or narrow width) decides whether it exists.

### Block handles (`editor/BlockHandle.vue`, `moveBlock.ts`, 1.12b)

- `DragHandleVue` from the TipTap package around a `BlockHandle` with the six dots, `aria-label`, and a Reka `DropdownMenu`. Tailwind only: opacity 20% to 100%, `cursor-grab`.
- `moveBlock.ts`: an extension with `Alt+ArrowUp` and `Alt+ArrowDown` that swap the top-level block holding the selection with its neighbour (a list item moves within its list). Announces the move through the live region.
- The block menu's "Turn into" reads `blockCommands.ts`.

### Table menu (`editor/TableMenu.vue`, 1.12b)

- Shown while `editor.isActive('table')`: Add row above and below, Add column before and after, Delete row, Delete column, Delete table. The first row stays a header unless it is deleted.

### Async editor (1.12b)

- `defineAsyncComponent` around `PageEditor` in `PageView.vue`, with a loading placeholder of the editor's minimum height. The sync store is not touched: the editor opens the page when it mounts.

### i18n

`editor.slash.*` (placeholder, no results, the count announcement, the categories), `editor.blocks.*` (label, description and keywords of each block, English and Dutch), `editor.toolbar.*`, `editor.handle.*`, `editor.table.*`, `editor.moved`. The lint rule needs every key written out; no keys built from a string.

## Tests

- **Block commands, Vitest:** each command makes the node the Markdown shortcut makes, with the trigger range deleted; `filterCommands` on prefixes, keywords, accents and Dutch; the order is kept.
- **Slash menu, Vitest with real editors in jsdom:** opens on `/` at a line start and after a space, not in a URL, a word or a code block; filters while typing; arrows, Enter, Escape, Tab; closes on a space after no match; deleting the slash closes it; the combobox attributes; read-only never opens it.
- **Toolbar, Vitest:** shown only on a coarse pointer and with focus; buttons keep the editor's focus; `aria-pressed` follows the marks; undo and redo run Yjs's and their disabled state follows `can()` (type, undo, the text is gone, redo, it is back, and another client's change is not undone); `useKeyboardInset` against a fake `visualViewport`.
- **Handle and moves, Vitest:** `Alt+Arrow` swaps blocks, stops at the ends, moves a list item inside its list, and is one undo step; the block menu's actions on a list, a table and a code block. **Property test** (the card's one critical-ish path: a move must never lose or duplicate content): random sequences of moves, deletes and duplicates on a generated document keep every block's text exactly once.
- **Table menu, Vitest:** each action on a 3 by 3 table, the header row, deleting the last row removes the table.
- **Playwright** (`web/e2e/editor-blocks.spec.ts`, desktop and phone, no CSP violation, which the fixture asserts):
  - every slash item, by mouse and by keyboard only, and the same blocks after a reload and in a second browser;
  - the slash menu in Dutch;
  - on the phone project, the toolbar shows when the editor is focused, undo and redo work, and with `visualViewport` faked smaller the toolbar moves up and the caret stays visible;
  - desktop: a block dragged with the mouse to a new place, seen in a second browser; `Alt+Arrow`; the block menu; a table made, grown, shrunk and removed;
  - the editor loads behind the page view (the title field is there before the editor).
- **Existing tests stay:** the 1.11 editor, sync and sanitising tests are not changed.

## Handoff

### 1.12a

Built on branch `feat/1.12a-slash-menu-toolbar`. Added `@tiptap/suggestion` and `@floating-ui/dom` (approved).

**As built**
- `editor/blockCommands.ts`: one list of 11 blocks (Text, H1-3, bullet, numbered, checklist, quote, code, table, divider) with labels, descriptions and search words per language; `filterCommands` matches word starts, ignoring case and accents.
- `editor/slashExtension.ts` (Suggestion, state object) and `SlashMenu.vue` (listbox, floating-ui through the style object, kept above the toolbar and inside the visual viewport).
- `editor/EditorToolbar.vue`: undo, redo, heading, bold, italic, bullet list, checklist, code, insert-block; roving tabindex, 44 px targets, buttons never take the focus. Shown on `pointer: coarse` or below 48 rem while the editor (or the toolbar) has focus.
- `composables/useKeyboardInset.ts` writes `--keyboard-inset`. The caret is kept above the toolbar by `handleScrollToSelection` in `PageEditor.vue`; ProseMirror's `scrollMargin` did not move the page's scroller (`main`), so it was not used.
- Tests: Vitest 560 passing (blockCommands, slash extension, SlashMenu, toolbar, keyboard inset); Playwright `editor-blocks.spec.ts` on desktop and phone; full e2e on both: 157 passed.

**Deviations and findings**
- `allowSpaces` is off, so the slash query is one word and a space closes the menu (also with matches). Search words are single words per block.
- The editor root stays `role="textbox"`; it gets `aria-controls`, `aria-haspopup` and `aria-activedescendant` while the menu is open, not `aria-expanded` (invalid on a textbox).
- TipTap's StarterKit keeps an empty paragraph after a last block that is not a paragraph; tests and e2e account for it.
- TipTap's Vue state reaches components after two animation frames, so toolbar pressed/disabled states lag a frame or two.
- Items arrive a microtask after the keystroke (Suggestion fetches asynchronously); tests `await flushPromises()`.

**Needs you:** the real-device Android check (decision 9) and `/code-review` at medium. The iPhone (WebKit) Playwright project was not run here.

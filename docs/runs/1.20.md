# Run 1.20: CI security

**Model:** S·low in the roadmap. Planned on Opus 5.5 high; builds on Sonnet 5.5 medium, not low: the workflow permissions, the auto-merge workflow (it runs with write access) and the licence script are where a low run cuts corners, and a mistake there weakens every later pull request without failing anything. `/code-review` at medium on Opus before the PR merges.

## Goal

Every pull request and every day on main, CI says whether Inkpact depends on something with a known vulnerability, something under a licence it cannot ship, or code with a security flaw CodeQL knows. Dependencies are kept current by Dependabot in small, grouped pull requests, with only harmless tooling patches merged on their own. No app to install: Dependabot is part of GitHub, as in GarageStack. None of it needs remembering: it runs, and it blocks a merge when it should.

## Decisions

1. **One run, three workflows.**
   - `security.yml` (new): `audit`, `licenses`, `dependency-review`.
   - `codeql.yml` (new).
   - `image.yml` (extended).

   No change to `ci.yml` but the bot exception in `commits`.
2. **`security.yml` runs on every pull request** (no path filter: a required check that does not run blocks the merge, and the jobs take about a minute), on push to main, **daily at 05:00 UTC** (advisories appear without any change here) and on request. `permissions: contents: read`.
   - **`audit`:** `pnpm audit --audit-level high` (everything) and `pnpm audit --prod --audit-level moderate` (what ships). NuGet: `dotnet list server package --vulnerable --include-transitive --format json`, read by a script (`.github/scripts/nuget-audit.mjs`, Node, no dependency), with the same rule: moderate or worse in `Inkpact.Api` and `Inkpact.Data`, high or worse in the test project. Question 3.
   - **NuGetAudit in the build** stays on but no longer fails it: `NU1901`–`NU1904` go into `WarningsNotAsErrors` in `Directory.Build.props`, with a comment pointing to the `audit` job. The build says what it found; the `audit` job decides, with one rule for npm and NuGet and a clear name in the checks list.
   - **`licenses`:** `.github/scripts/check-licenses.mjs` (Node, no dependency) reads `pnpm -r licenses list --json` (all workspaces, dev too: tooling runs on contributors' machines and in CI) and the licence of every NuGet package (`dotnet list package --include-transitive --format json`, then each `.nuspec` in the restore cache). It checks them against `.github/license-policy.json`:
     - **allowed:** licences compatible with AGPL-3.0 — MIT, MIT-0, ISC, BSD-2-Clause, BSD-3-Clause, 0BSD, Apache-2.0, MPL-2.0, BlueOak-1.0.0, CC0-1.0, CC-BY-4.0, Unlicense, Zlib, Python-2.0, PostgreSQL, LGPL-2.1-or-later, LGPL-3.0, GPL-3.0, AGPL-3.0;
     - an `OR` expression passes when one side does, `AND` when both do;
     - **per-package entries** for what has no SPDX expression (`xunit.abstractions` → Apache-2.0, from its licence URL), each with the reason;
     - **anything else fails,** naming the package, its version, its licence and where it comes from: GPL-2.0-only, SSPL, BUSL, the Commons Clause, CC-BY-NC/ND, a custom or missing licence (the FluentAssertions v8 kind of change).

     `pnpm check:licenses` runs it locally.
   - **`dependency-review`** (pull requests only): `actions/dependency-review-action`, failing on a new dependency with a moderate or worse advisory. It also shows each new dependency's licence and OpenSSF score in the job summary. Licences are not checked twice: the policy file is the one place.
3. **CodeQL, advanced setup** (`codeql.yml`, versioned and pinned like every other workflow, rather than the settings toggle).
   - **Languages:** `csharp` (built: setup-dotnet from `global.json`, `dotnet build server`), `javascript-typescript` (no build) and `actions` (workflow injection, unpinned actions, token permissions).
   - **Queries:** `security-extended`.
   - **Runs:** on pull requests, on push to main, and weekly.
   - **Config** (`.github/codeql/codeql-config.yml`): `paths-ignore` for `docs/design/**`, `spike/**` and `**/dist/**`.
   - **Permissions:** `security-events: write` for that job only.
4. **Trivy, extended in `image.yml`:**
   - the existing gate stays as it is;
   - a second run writes all findings as SARIF and uploads them to code scanning, so they are tracked and visible;
   - a `misconfig` scan of the Dockerfile and the compose files (HIGH and CRITICAL fail);
   - a weekly scan of the published `ghcr.io/gotgeeks/inkpact:edge`, the image people actually pull.
5. **Dependabot for every ecosystem** (the choice: no app to install, the same as GarageStack). `.github/dependabot.yml` grows from two entries to all of them. Every entry has:
   - a schedule of Mondays 07:00 Europe/Amsterdam;
   - **`cooldown: default-days: 3`**, longer than pnpm's one-day `minimumReleaseAge`, so Dependabot never proposes a version pnpm would refuse to install;
   - the `dependencies` label;
   - commit messages `build(deps): …` for runtime and `chore(deps): …` for development (`prefix` and `prefix-development`).

   **The entries:**
   - **npm** (`/`, the pnpm workspace: `web` and the sidecar). Groups:
     - `tiptap` (`@tiptap/*` but `@tiptap/y-tiptap`);
     - `yjs` (`yjs`, `lib0`, `y-protocols`, `@tiptap/y-tiptap`: one pull request, never automerged);
     - `vue` (`vue`, `vue-router`, `vue-i18n`, `pinia`, `reka-ui`, `@vitejs/plugin-vue`);
     - `vite` (`vite`, `@tailwindcss/vite`, `tailwindcss`);
     - `playwright` (`@playwright/test`, `@axe-core/playwright`).
     - Four tooling groups that auto-merge may take: `web-lint` (`eslint`, `@eslint/*`, `eslint-*`, `eslint-plugin-*`, `typescript-eslint`, `@intlify/eslint-plugin-vue-i18n`, `prettier`), `web-types` (`@types/*`, `vue-tsc`), `web-unit-tests` (`vitest`, `@vue/test-utils`, `jsdom`) and `commitlint` (`@commitlint/*`).
     - `typescript` majors ignored, with GarageStack's reason (vue-tsc needs the TypeScript 6 API).
   - **NuGet** (`/server`, central versions in `Directory.Packages.props`). Groups:
     - `dotnet-platform` (`Microsoft.AspNetCore.*`, `Microsoft.EntityFrameworkCore*`, `Npgsql*`);
     - `test-framework` (`xunit*`, `Microsoft.NET.Test.Sdk`);
     - `test-libraries` (`Shouldly`, `NSubstitute`, `FsCheck*`, `Testcontainers*`).
   - **GitHub Actions** (`/` and `/.github/actions/*`): digests kept, with the tag in the comment. Groups:
     - `actions` (`actions/*`);
     - `docker-actions` (`docker/*`);
     - `codeql-action` (`github/codeql-action*`: every step must run the same version, or CodeQL fails, as GarageStack found).
   - **Docker** (`/`, the Dockerfile; already there): Node majors ignored, with the reason.
   - **The SDK pin:** the `dotnet/sdk` image and `global.json` are moved by two entries, which Dependabot cannot group across ecosystems. A comment next to both says so, and CI fails when they differ (a check in `image.yml`'s Inspect step).
   - **docker-compose** (`/deploy`): Postgres majors ignored (a major cannot open an older data directory; `deploy/inkpact.sh` does the dump and restore).
   - **dotnet-sdk** (`/`): already there.
   - **Security updates** (on in the repository settings) use the same file, so they come grouped and labelled the same way, without the cooldown.
   - **pnpm 12:** Dependabot supports pnpm lockfile v9, which is what `pnpm-lock.yaml` is. Whether it updates the lockfile the way pnpm 12 would is checked on its first pull requests: `pnpm install --frozen-lockfile` in CI fails a lockfile it got wrong, and the handoff says what happened.
6. **Auto-merge only for patch updates of web dev tooling** (question 1). `.github/workflows/auto-merge.yml`, after GarageStack's:
   - **Trigger:** `pull_request_target`, only for pull requests whose author is `dependabot[bot]` and whose branch is in this repository. It never checks out the pull request's code.
   - **Rule:** `dependabot/fetch-metadata` (pinned by digest) says what the update is; the workflow runs `gh pr merge --auto --squash` when it is a **patch** in one of the tooling groups (`web-lint`, `web-types`, `web-unit-tests`, `commitlint`). Their whole effect is checked by the jobs a pull request runs (lint, types, Vitest).
   - **Never automerged:**
     - runtime dependencies;
     - NuGet (a pull request does not run the server tests);
     - Playwright;
     - GitHub Actions (they run with the repository's token);
     - the Yjs group;
     - anything minor or major.
   - **Permissions:** `contents: write` and `pull-requests: write` for that one job, and nothing else in the file.
   - **Checks:** the merge waits for every required check, as auto-merge does. No approval is needed: the ruleset asks for none.
   - **Needs:** "Allow auto-merge" on in the repository settings.
7. **The commit checks stay as they are:** `ci.yml` already lets `dependabot[bot]` through the commitlint and sign-off checks (GitHub sets a pull request's author; a bot cannot sign off).
8. **Required checks** (question 3):
   - `audit`, `licenses` and `dependency-review` join the ruleset's required checks.
   - CodeQL is not a required job: its analyses take minutes on a pull request. Instead, the ruleset's code scanning rule blocks a merge that adds a **high or critical** CodeQL or Trivy alert.
   - I make the ruleset change with `gh api` after the PR merges, so its new checks exist when they become required.
9. **No new dependency in the repository and no app.** The scripts are plain Node. The actions are GitHub's (`github/codeql-action`, `actions/dependency-review-action`), Dependabot's (`dependabot/fetch-metadata`) and Aqua's (Trivy, already used), all pinned by digest.

## Done when

- A pull request runs `audit`, `licenses`, `dependency-review` and CodeQL, and they pass on the code as it is.
- A deliberately broken branch, not merged, shows each check failing for the right reason:
  - an old `dompurify` with a known advisory fails `audit` and `dependency-review`;
  - a package with an unknown licence fails `licenses`, naming it;
  - a workflow with `${{ github.event.pull_request.title }}` in a `run:` fails CodeQL's `actions` analysis;
  - a vulnerable NuGet package fails `audit` but not the build.
- Trivy's findings and CodeQL's alerts are on the Security tab. The weekly scan of `edge` runs on request.
- The first Monday's Dependabot pull requests have the right groups, commit messages, labels and cooldown, and their lockfile passes `--frozen-lockfile`.
- A web dev-tooling patch automerges after its checks; a runtime patch and a NuGet patch wait.
- `security.yml` runs daily on main.

## Tests

- **`check-licenses.mjs` and `nuget-audit.mjs` are tested with `node --test`** (no dependency), against small fixture files:
  - an allowed licence, an `OR` and an `AND` expression;
  - a per-package entry;
  - a missing licence and a disallowed one;
  - a moderate advisory in the test project (passes) and in `Inkpact.Api` (fails).
- **The auto-merge rule is a small function too** (`.github/scripts/automerge.mjs`). The workflow passes it the metadata and it says merge or not. It is tested with:
  - a patch in each tooling group;
  - a patch in `yjs`;
  - a minor in `web-lint`;
  - a NuGet patch;
  - a GitHub Actions patch.
- **These tests run** as the first step of the `licenses` job in `security.yml`, so a change to a script is tested where it runs.
- **The broken branch of "Done when" is the end-to-end test of the workflows.** It is pushed, its checks are read, and it is deleted. The PR lists what each check said.

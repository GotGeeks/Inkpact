# Run 0.1: Yjs relay spike

**Model:** S·med (executed on Opus 5.5)

## Goal

An ASP.NET Core WebSocket endpoint that relays Yjs updates between the clients of one page, a minimal Vite page with TipTap and the Yjs collaboration extension, and Postgres in a compose file.

## Inputs

- `docs/architecture.md`: "Sync flow" steps 1–3, "Server CRDT handling" (opaque blobs), Phase 0 table.

## Done when

- Two tabs on `?page=x` show each other's typing within a second; a tab on `?page=y` sees nothing.
- A tab that joins late receives the current text.
- Server unit tests pass; `pnpm check:relay` passes against a running server.

## How to run

```bash
docker compose -f spike/docker-compose.yml up -d        # Postgres on 127.0.0.1:5433 (unused until 0.2)
dotnet run --project spike/server/Spike.Server           # http://localhost:5080
pnpm --dir spike/client install --frozen-lockfile
pnpm --dir spike/client dev                              # http://localhost:5173/?page=x
pnpm --dir spike/client check:relay                      # headless Yjs clients against :5080
dotnet test spike/server
```

## Design notes

- `/ws?page=<id>`: the server keeps an in-memory set of sockets per page and forwards every binary message unchanged to the other sockets. It never decodes Yjs.
- Each connection has its own send queue (a `Channel`), because a WebSocket allows one `SendAsync` at a time.
- The client uses the `y-protocols` sync messages with y-websocket framing (varuint type 0 = sync). Because the relay keeps no state, peers answer each other's step 1. On every (re)connect a client also pushes its full state, since nobody sends step 1 back to it. That is how offline edits get through.
- Spike rules relaxed: no i18n, plain CSS, no CSP, no auth or Origin check.

## Handoff

- **Done:** relay hub with 4 xUnit tests (same-page delivery without echo, page isolation, multi-frame messages, missing page rejected); TipTap + Yjs client; headless `check:relay` script covering late join, concurrent edits and offline-then-reconnect merge; Vite proxy for `/ws`; Postgres compose file.
- **Left for 0.2:** persistence and server-side sync step 2 (removes the full-state push on reconnect), page-id envelope for one socket per session, awareness/presence, multi-tab of the same user. Typing in two real browser tabs was checked by hand and works.
- **Surprising:** nothing blocking. Send queues are unbounded (a slow client grows memory, so bound them in 1.09). The client bundle is about 507 kB minified (160 kB gzipped) in one chunk, so lazy-loading the editor (1.12) will matter.

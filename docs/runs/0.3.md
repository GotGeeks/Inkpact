# Run 0.3: scripted sync scenarios in Playwright

**Model:** S·med

## Goal

Scripted browser test: two browsers editing at once, one going offline and reconnecting, and a server restart mid-edit. Reused as integration and e2e tests in 1A.

## Inputs

- `docs/architecture.md`: Phase 0 table, "Testing" (Playwright, two clients editing one page, one going offline).
- Run 0.2 handoff.

## Done when

- `pnpm --dir spike/client e2e` passes all three scenarios, also when repeated (`--repeat-each=5`).
- The suite starts and stops its own server and Vite, and leaves nothing running.

## How to run

```bash
docker compose -f spike/docker-compose.yml up -d --wait   # Postgres on 127.0.0.1:5434
pnpm --dir spike/client e2e                                # builds the server, then runs Playwright
```

The suite uses ports 5081 (server) and 5174 (Vite), so a dev setup on 5080/5173 can keep running. Set `E2E_SERVER_LOG=<file>` to keep the server output.

## Scenarios (`spike/client/e2e/sync.spec.ts`)

1. **Concurrent typing.** Two separate browser contexts type into one page at the same time; both editors end up with identical text containing every typed character, in order.
2. **Offline and back.** One browser's WebSocket is cut and reconnects are refused. It shows "disconnected", both sides keep typing, and the online side does not see the offline edit. After going back online both converge on everything.
3. **Server restart mid-edit.** The server process is killed; both browsers show "disconnected" and keep typing; the server is started again; both converge on all three pieces. A brand-new third browser then gets the same text from Postgres alone.

## Notes

- `ServerProcess` (`e2e/server.ts`) runs the built `Spike.Server.dll` as a child process, so a test can kill and restart it. It is built to `bin/e2e` so a running dev server doesn't lock the output.
- Chromium's `context.setOffline` leaves an open WebSocket connected. The offline scenario therefore routes the socket through `page.routeWebSocket` and closes the route to cut it.
- Vite's proxy target is now `SPIKE_SERVER` (default `ws://localhost:5080`), so the suite can point it at its own server.

## Handoff

- **Done:** three Playwright scenarios, 15 of 15 passing in a repeated run (about 24 s); the server and Vite are started and stopped by the suite. New dev dependencies: `@playwright/test` and `@types/node` (types only).
- **Finding for the 0.7 findings and for 1.11:** two clients typing into a brand-new empty page at the same moment each create their own first paragraph, so the page ends up with two paragraphs. Nothing is lost and both sides agree, but it is visible. The editor in 1.11 should create the first paragraph once, at page creation, or accept it. The test ignores line breaks for this reason.
- **Left:** no Android or touch coverage (0.6). Offline here means a cut connection; IndexedDB persistence of Yjs state across a reload is phase 1B (B.6), so a reload while offline still loses the unsent edits. The scenarios have no timing assertions; the numbers come from `check:sync` (0.2).

# Run 1.19: Responsive and accessibility pass

**Model:** S·med in the roadmap. Planned on Opus 5.5 high; builds on Sonnet 5.5 medium. `/code-review` at medium on Opus before the PR merges: nothing here touches data, but a check that passes for the wrong reason would hide every later regression.

## Goal

Every screen works on a 320-pixel-wide phone without scrolling sideways, every control can be reached and used with the keyboard alone, every control has a name a screen reader says, and text and controls have the contrast WCAG 2.2 AA asks for. Machines check all of it in Playwright, on desktop and on the phone viewports, so a later run cannot quietly undo it.

This is the baseline the roadmap promises for phase 1A, not the full audit (that is "before v1.0" in the risks).

## What the code is now (found while planning)

1. **Much is already in place.** Landmarks (`aside` with a name, `main`), `lang` on `<html>` that follows the language, labelled fields with their error tied to the input, a roving tab stop in the tree and the toolbar, Reka UI's dialogs and menus (focus trap, Escape, focus back), 44-pixel targets on most phone controls, `role="alert"` and `role="status"` where a message appears, and Playwright on three devices that fails on any CSP violation.
2. **No automated accessibility check exists.** Nothing in the repo runs axe or anything like it; the specs check behaviour, not names, roles or contrast.
3. **The focus ring fails its contrast in eight places.** `focus-visible:outline-primary-container` (`#4f46e5`) is 3.15:1 on the canvas and 2.4 to 2.9:1 on the panel and the menus, under the 3:1 of WCAG 1.4.11. Sixteen other places use `outline-primary` (`#c3c0ff`, 8.8 to 11.6:1). `DESIGN.md` names `#4F46E5` for focus rings, which is where it came from.
4. **The edge of a text field is not visible enough.** `TextField` and the tree's rename field draw it in `border-subtle` (`#232838`): 1.35:1 on the canvas. A field needs 3:1 to be seen as one (1.4.11). `outline` (`#918fa1`) is 6.3:1.
5. **A done to-do's text is 40 % opacity** (`editorClasses.ts`, from `DESIGN.md`): about 3:1, under the 4.5:1 of text. The toolbar's disabled buttons are 40 % too, which is allowed for a disabled control.
6. **The tab's title is always "Inkpact".** Nothing sets `document.title` per screen or per page (WCAG 2.4.2), and a screen reader hears nothing when a page opens from the tree.
7. **No skip link.** On the desktop the sidebar's tree comes before the page in the tab order. The landmarks let a screen reader jump, but a sighted keyboard user tabs through the sidebar's controls first (2.4.1).
8. **Some phone targets are small.** The tree's expand and row-menu buttons are 28 px (`size-7`), the link menu's and table menu's buttons 36 px (`min-h-9`), the block handle's menu items 36 px. `DESIGN.md` asks 44 px on touch; WCAG 2.2 AA (2.5.8) asks 24 px, which they meet.
9. **Nothing checks 320 px.** The phone projects are 412 px (Pixel 7) and 393 px (iPhone 15). Reflow (1.4.10) is defined at 320 CSS pixels, which is also a phone with large text.

## Decisions

1. **One run.** The fixes are small and spread out; the checks are what takes the time, and they need every screen in one place.
2. **axe in Playwright** (`@axe-core/playwright`, a dev dependency, MPL-2.0; question 1). A new spec, `web/e2e/a11y.spec.ts`, opens every screen and state on all three device projects and runs axe with the WCAG 2.0, 2.1 and 2.2 A and AA rules: no violations. Screens and states:
   - login (with an error shown), setup (in the setup project, before the administrator exists);
   - start page, a page with every block (headings, lists, a to-do done and open, a table, code, a picture, a file), a page in the trash, a page not found;
   - the trash, empty and with pages;
   - the import page before a file, and its report;
   - the search dialog with results and with none;
   - the move dialog, the user menu, a tree row's menu, the drawer (phone);
   - the editor's slash menu, link menu, table menu, block menu (desktop) and toolbar (phone);
   - a notice (a page moved to the trash, with Undo).

   An exception is written as a disabled rule on one element with the reason next to it, never as a rule off for the whole spec.
3. **Reflow at 320 px:** a fourth device project, `narrow` (320 × 640, touch, Chromium), runs `a11y.spec.ts` only. Every screen above passes axe there and has no sideways scroll (`document.scrollingElement.scrollWidth <= clientWidth`, and the same for `main`). A wide table or a long code line scrolls inside its own block, which is allowed.
4. **Contrast, also where axe does not look.** axe checks text, not focus rings or the edges of fields. A Vitest test (`web/src/contrast.test.ts`) reads the tokens from `style.css` and checks the pairs the app uses: text 4.5:1, large text and controls 3:1, on every surface they sit on. A second test fails on `outline-primary-container` in any component and on a field drawn in `border-subtle`. Fixes:
   - every focus ring is `outline-primary` (finding 3);
   - text fields have `border-outline` (finding 4);
   - a done to-do is struck through in `text-outline` (6.3:1) instead of 40 % (finding 5; question 2);
   - `DESIGN.md` gets a line under "Colors" that focus rings use `primary` (`#c3c0ff`), because `#4F46E5` fails on these surfaces.
5. **The tab's title and the page that opens** (question 3):
   - `document.title` is "Page title – Inkpact" on a page ("Untitled – Inkpact" without a title), and the screen's name on the others ("Trash – Inkpact", "Import – Inkpact", "Sign in – Inkpact"), from i18n, updated when the title changes;
   - when a page opens, a polite live region in the shell says "Opened: Page title". The focus stays where it was, so a keyboard user walking the tree keeps their place (Enter and Space in the tree open a page and leave the focus on its row); the skip link of decision 6 takes them to the page.
6. **A skip link** first in the shell: "Skip to page", visible when focused, moves the focus to `main`. On the phone the header comes first and has two buttons, so the link is there too but matters less.
7. **Touch targets of 44 px on touch screens** (`pointer-coarse:`), the desktop keeping its density (question 4): the tree's expand and menu buttons, the link and table menus' buttons, the block menu's items. A Playwright check on the phone projects measures every visible button, link and field of each screen in decision 2: at least 44 × 44, except links inside text (WCAG's inline exception) and the editor's own content.
8. **Keyboard walk on the desktop:** one spec does a session without the mouse: sign in, skip link, open a page from the tree, type in it, rename it from the row's menu, move it, open search with Ctrl+K and open a result, open the user menu and start the export check, put a page in the trash, restore it from the trash, sign out. Each step checks where the focus is and that it is visible (an outline of at least 2 px).
9. **No new screens and no new behaviour.** What a check finds that is more than a class or an attribute (a control that cannot be reached at all, say) is fixed if small, and otherwise written down under "Left for later" with an issue.

## Questions

1. **May `@axe-core/playwright` be added** (dev dependency, MPL-2.0, maintained by Deque, the standard engine behind Lighthouse's accessibility score)? It is the only way to check names, roles and text contrast on every screen without writing a checker of our own. **Recommended: yes.** Without it the run checks only what decisions 3, 4, 7 and 8 measure by hand.
2. **A done to-do:** struck through in `text-outline` (6.3:1, still clearly faded next to the open ones), or keep the design's 40 % (fails 4.5:1)? **Recommended: `text-outline`.**
3. **When a page opens from the tree:** the focus stays in the tree and a live region says which page opened, or the focus moves to the page's title? **Recommended: stays, with the announcement,** so the tree can be walked page by page; the skip link takes the focus to the page.
4. **Phone targets:** 44 px on touch screens for every control, as `DESIGN.md` asks, or WCAG's 24 px, which they already meet? **Recommended: 44 px,** only on touch screens (`pointer-coarse:`), so the desktop keeps its density.

## Handoff

### 1.19, built on Sonnet 5.5

**Done:** decisions 1 to 9 but as listed under "Where the plan changed". One new dev dependency (`@axe-core/playwright`), no migration, no server change.

**What was built:**
- **`web/e2e/a11y.spec.ts`** (13 tests, on desktop, Pixel 7, iPhone 15 and the new 320 px `narrow` project): axe with the WCAG 2.0 to 2.2 A and AA tags, sideways scrolling of the page and of `main`, and (touch projects) every control at least 44 by 44. Screens and states: sign-in (empty and with an error), the start page, the sidebar (the drawer on a phone) and a row's menu, a page with headings, a list, a to-do, a quote, code, a table and a rule, the slash menu (with and without results), the block menu (desktop) or the toolbar (touch), the table menu, a notice with Undo, a page in the trash, the trash, a page not found, the search dialog (with and without results), the move dialog, the account menu, the import page, and the start page and sidebar in Dutch.
- **`web/e2e/keyboard.spec.ts`** (desktop): sign in and out with the keyboard alone; then the skip link, a new page, rename (F2), the row menu (Shift+F10) and the move dialog, search (Ctrl+K), typing in the page, the export (typed into the account menu, a download), Delete, the trash link and Restore. Each step checks where the focus is, and that it shows.
- **`web/src/contrast.test.ts`** (Vitest, 68 cases): token pairs read from `style.css`, and the classes that failed before cannot come back.
- **`useDocumentTitle`** (in `App.vue`): "Title – Inkpact", "Untitled – Inkpact", "Trash – Inkpact" and the others, in both languages, following renames. **Skip link** and a polite **live region** ("Opened: Title") in `AppShell`.
- **`a11y.*` keys** in both languages.

**Found by the checks and fixed (all real):**
1. **The focus was invisible on the tree's rows, text fields and the move dialog's items.** `outline-none` in Tailwind 4 sets `--tw-outline-style: none`, and `focus-visible:outline-2` uses that variable, so the ring was never drawn. Found by the keyboard walk (axe does not see it). `outline-none` is gone from those elements, and `contrast.test.ts` fails on the combination.
2. **Focus rings in `primary-container`** (eight places, 2.4 to 3.15:1) are `primary` now; `DESIGN.md` says so.
3. **The edge of a text field** was 1.35:1 (`border-subtle`); it is `outline` (6.3:1).
4. **A done to-do** was faded to about 3:1; it is struck through in `outline` (6.3:1).
5. **The account menu's button** had the name "Account menu" but showed the person's name (WCAG 2.5.3): it is now "Jos, account menu".
6. **The export item's hint** was part of the item's visible text but not of its name: the hint is now a label under the item, which describes it.
7. **The search field pointed `aria-activedescendant` at a result that was no longer there** after "Nothing found".
8. **Targets under 44 px on touch screens:** the tree's expand and menu buttons (28), the link, table and block menus' buttons (36), the notice's Dismiss (32), the page title field (36), a search result (42). The to-do checkbox is 24 px (was 18; WCAG 2.2 asks 24).

**Where the plan changed or was open:**
1. **Exceptions:** one, in `a11y.spec.ts` with its reason: the slash menu's scroll area is not focusable (the editor keeps the focus; the options are reached with `aria-activedescendant`). axe's `aria-hidden-focus` is not run while a modal menu or dialog is open (Reka UI hides the app behind it and traps the focus), found by `[data-aria-hidden]`; with nothing open it runs.
2. **The announcement says what is open when it opens:** a new page is announced as "Untitled" (it has no title yet) and a rename is not announced. Opening the page that is already open says nothing new; opening another page with the same title does (the text is cleared first).
3. **Not covered by axe:** the link menu (it needs a link in the text), the import report (it needs a Joplin export, and imports of the three devices exclude each other), the setup page (closed once the account exists; its form is the sign-in's), a picture and a file in a page, the version history and the drag handle's dragging. The import report and the setup page are for the trial or a later run.
4. **The title and announcement have Vitest tests** (`useDocumentTitle.test.ts`, `AppShell.test.ts`) and the keyboard walk checks them in a browser; there is no separate phone test.
5. **Drop indicator in the tree** now outlines in `primary` too; its test compares class names exactly.

**Checked by tests:** see above; the full `pnpm check` passed (see the PR for the numbers).

**For the trial:** see above.

**Review (Opus 5.5, medium), all 9 findings fixed:**
1. **A page in the trash got the title "This page could not be found".** The title and the announcement looked the page up in the live tree, which has no trashed pages. They now read a small store, `currentPage`, that the page view fills with the page as it fetched it (found, in the trash, or not found).
2. **Opening a page in the trash announced nothing.** The same cause and fix.
3. **A second page with the same title ("Untitled") was not announced,** since the text did not change. It is cleared first and set on the next tick.
4. **The editor's block-move check no longer looked at a live region.** It is scoped to the editor's own (`editor-announcer`) and checks `aria-live`.
5. **The page title field showed no focus ring.** It has one now, and the keyboard walk checks it.
6. **The search fix had no unit test.** `SearchDialog.test.ts` checks that the field points at no result after "Nothing found" (and fails without the fix).
7, 8. **A duplicate `pointer-coarse:min-h-11`** in the link and table menus.
9. **Deep rows on a narrow phone kept little room for the title.** The indent steps are 12 px on a touch screen (16 on a desktop), and `a11y.spec.ts` opens a branch five levels deep on every device: no sideways scrolling, and the title keeps at least a third of the row.

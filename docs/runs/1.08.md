# Run 1.08: tree UI

**Model:** O·high → S·med (planned on Opus 5.5, built on Sonnet)

## Goal

A person can see, open, create, rename, nest, reorder and trash pages from a sidebar, with the mouse, the keyboard or a phone. The server stays the source of truth: the client asks, then reloads the tree.

## Inputs

- `docs/architecture.md`: "Tree and metadata conflicts", "Permission resolution".
- Run 1.07: the tree API (list, create, rename, move, trash, restore; neighbours, never keys) and its error codes.
- `docs/design/`: visual reference only. Not built: favourites, search, storage widget, templates, graph, sharing.

## Done when

- The sidebar shows the first workspace as a tree; branches open and close, and stay as left after a reload.
- Create, rename, nest, reorder, trash (with Undo) and restore work with a mouse, with the keyboard alone, and on a phone.
- The trash view lists what can be restored; a page opened from the trash says so.
- Every string is in `en.json` and `nl.json`; no CSP violation in any e2e test.

## Decisions (confirmed)

1. **No drag library.** Mouse users drag with native HTML5 drag and drop. The keyboard has Alt+arrows. A "Move to…" dialog is the only way to move a page on a phone, where a finger would scroll.
2. **ARIA tree pattern.** Planned as Reka `Tree`; built as an own component on the same pattern (see below).
3. **Undo toast after trashing.** First workspace only. A user menu (name, language, sign out, sign out everywhere) replaces the old home page.
4. **Not built:** "delete forever" and emptying the trash (no endpoint; decided later), anything from the designs listed above.

## As built

- **Structure:** a nested route `/` → `AppShell` with the start page, `p/:pageId` and `trash`. Below 48 rem the sidebar is a drawer (Reka Dialog); above, it stays beside the page.
- **State:** `useTreeStore` (load, create, rename, move, trash, restore; no optimistic updates). Failures become toasts through `useNotificationsStore`. Open branches are kept per workspace in `localStorage`, guarded by try/catch.
- **Pure logic in `tree/treeModel.ts`** (51 tests): visible rows, drop zones (top quarter before, bottom quarter after, middle inside), `dropPosition`, `keyboardMove`, `moveTargets`. Drops on the page itself, on something below it, or that change nothing are refused.
- **Keyboard:** arrows, Home/End, Left/Right (collapse, expand, parent), Enter/Space, F2, Delete, Alt+arrows (move, indent, outdent), ContextMenu/Shift+F10. Roving tabindex: one row is in the tab order.
- **Dragging:** only with a fine pointer and edit rights; held for 700 ms over a closed branch it opens.
- **Tests:** 302 unit and component tests; the e2e suite now has `tree-ui.spec.ts` (create, nest, rename, Escape, Move to…, keyboard, mouse drag, trash, Undo, restore, trashed-page banner, drawer, touch target size) on desktop, Pixel 7 and iPhone, and 172 tests pass, four runs in a row.

## Changes from the plan

- **Own tree instead of Reka `Tree`.** Reka's `Tree` has no drop targets, Alt+arrow moves or a row menu, and wrapping it for those would have cost more than the ARIA pattern (role `tree`/`treeitem`, `aria-level`, `aria-expanded`, `aria-setsize`/`posinset`) it provides. Menus, dialogs and toasts do come from Reka.
- **On a phone the drawer closes when a page is trashed and when the trash link is used.** Otherwise the Undo toast sits behind the modal drawer where nobody can reach it.
- **A restore "to the top level" is not reachable from the UI.** The trash lists only the top of each trashed branch, so a page whose parent is also trashed cannot be restored on its own; once the parent comes back, the child shows up in the trash by itself. The `restoredTo: root` notice is covered by component tests, not e2e.

## Found while testing

- The e2e projects share one workspace and run in parallel. Tests therefore use titles unique to the project and run, put pages that must be neighbours under a parent of their own, and wait for a notice before going to another page.
- A WebKit CSP violation (`<style>body {}</style>`) shows up only in tests that already failed. It is Playwright's failure screenshot, not the app.
- jsdom has no `CSS.escape`; focus lookup uses `dataset.pageId`.

# Run 1.11: editor and sync client

**Model:** O·high → S·high (1.11a) and S·med (1.11b) (planned on Opus 5.5, built on Sonnet). The roadmap says S·med; the sync client is a sync path, so 1.11a is built at high effort and gets `/code-review` at high on Opus before it merges. This card is the Opus pass for both PRs.

## Goal

The first real editor: a page shows its title as a field above a TipTap editor with headings, lists, checklists, code blocks, tables and links, and the content syncs live through the hub. A TypeScript sync client keeps one socket per tab, notices a dead connection by itself, reconnects with backoff and resyncs in diff and log mode, so nothing typed offline or during an outage is lost. The spike's browser scenarios 1, 2, 4 and 5 become Playwright tests against the real server. Pasted HTML is sanitised with DOMPurify, and the strict CSP stays as it is.

## Decisions (confirmed)

All seven were approved as proposed, together with the new dependencies and the ProseMirror CSS exception (decisions 6 and 7), and the order 1.11a first, then 1.11b. Each says what was chosen and what else was weighed.

1. **Split into 1.11a (sync client) and 1.11b (editor).** As one run it touches about 30 files with tests and docs.
   - **1.11a:** protocol, sync client, Pinia store, the status pill on the page, unit and randomised tests, an e2e for connection states. About 15 files. The page subscribes without an editor (read-only, nothing sent), which is enough to test the client against the real server.
   - **1.11b:** TipTap, the first paragraph, title field, paste sanitising, editor styles, scenarios 1, 2, 4 and 5. About 16 files.
   - Weighed: splitting by protocol and UI instead would leave 1.11a with no browser test at all.
2. **The sync client lives in `web/src/sync/`,** framework-free TypeScript (`protocol.ts`, `syncClient.ts`) that runs under Node in Vitest, wrapped by a Pinia store (`stores/sync.ts`) that turns its callbacks into refs.
   - Weighed: a workspace package (`packages/sync-client`). Nothing else needs it: the Electron app reuses the web bundle, and the sidecar has no business with sockets. It can move out later without changing its code.
3. **The first paragraph comes from one fixed Yjs update that every client applies,** so it exists exactly once whoever gets there first.
   - The update is built in code: a fresh `Y.Doc` with a fixed client id (a constant, never to be changed: it is part of the stored format) inserts into `default` a `paragraph` element holding one empty `Y.XmlText`. Same id and clock everywhere, so Yjs treats every copy as the same item and the second one is a no-op.
   - The editor applies it to a new page document **before** subscribing, so the subscribe's state vector already contains it and the server's diff leaves it out when the page has it. A page that never had it (every page made before this run) gets it on first open: no migration.
   - The empty `XmlText` matters: without it two clients typing at once each create their own text node in the paragraph, which is the spike's two-paragraphs finding one level down. **Prove this first in 1.11b** (two editors, concurrent typing, one paragraph with one text). If y-tiptap replaces the empty text, stop and rethink before building on it.
   - Reapplying after the person deleted that paragraph does not bring it back: the deletion is in the delete set.
   - A real client that drew the same random id is renamed by Yjs when the update arrives (it changes its own id when a remote update uses it).
   - **Consequence for 1.15:** an imported page must start from the same update, or clients add an empty paragraph at the top. Put it in the architecture.
   - Weighed: the server writing the same bytes when it creates a page. It needs a C# constant pinned against Yjs, a migration for existing pages, and phase 3's offline page creation would still need the client rule. The client rule alone covers all three.
4. **The title is a field above the editor that saves through the existing `PATCH /api/pages/{id}`** (the tree store's `rename`, with `expectedVersion`). Never in the Yjs document: titles are metadata.
   - **When it saves:** on Enter (which then puts the caret at the start of the editor), on blur, and after 1 s without typing; only when the text changed. Saving on every key would raise the page version, lock the workspace row and reload the tree per key.
   - **Conflicts:** last write wins, as the tree rules say; a `conflict: true` answer needs no UI.
   - **Read-only** for viewers (`tree.canEdit`) and for a page in the trash (the server refuses `page_in_trash`), while the content of a page in the trash stays editable ("Edit vs delete").
   - **Not live across tabs:** another tab sees a new title when its tree reloads. Pushing tree changes over the socket is a later run; say so in the handoff.
5. **DOMPurify on paste: yes,** in TipTap's `transformPastedHTML`, which ProseMirror also runs on dropped HTML.
   - An allow-list of exactly what the schema can hold (see "Paste and links"), as the architecture requires, before ProseMirror's own parse. ProseMirror already parses in a detached document and drops what the schema does not know; DOMPurify is the second wall, and the list the server-side import check (1.15) mirrors.
   - **Paste is not the only way in:** content from other clients arrives through Yjs and never passes a paste handler. For that the schema is the wall, and the one attribute that becomes a URL (a link's `href`) is checked when it is rendered. Both get tests.
   - Weighed: the schema alone. Less code, but the architecture names DOMPurify, and the import needs a shared allow-list anyway.
6. **New dependencies** (asking now, none has install scripts, all already used in the spike):
   - **1.11a:** `yjs` 13.6.33 (the sidecar's version, already in the lockfile), `lib0` 0.2.119 (Yjs's own encoder, already in the lockfile; the client imports `lib0/encoding` and `lib0/decoding` directly, as the spike did), `y-protocols` 1.0.x (the awareness encoding; new to the lockfile, depends only on `lib0`). All MIT.
   - **1.11b:** `@tiptap/core`, `@tiptap/pm`, `@tiptap/vue-3`, `@tiptap/starter-kit`, `@tiptap/extension-collaboration` and its peer `@tiptap/y-tiptap`, `@tiptap/extension-list` (task list and task item), `@tiptap/extension-table`, `@tiptap/extensions` (placeholder), all on the spike's 3.x line; `dompurify` 3.x (MPL-2.0 or Apache-2.0, ships its own types). `extension-list` and `extensions` are already dependencies of the starter kit; pnpm only lets `web` import its direct ones.
   - **Not proposed:** a syntax highlighter for code blocks (`lowlight`), collaboration cursors, `fast-check` (the randomised test uses a seeded generator written in the test).
   - There must be exactly one `yjs` in the lockfile: two copies break sync silently (the spike's Vite finding). Check with `pnpm why yjs`.
7. **ProseMirror's own CSS.** TipTap injects a `<style>` element by default, which the CSP blocks. So `injectCSS: false`, and:
   - the document's look (headings, lists, checklist, code block, table, link, placeholder) as Tailwind arbitrary variants on the editor root (`[&_h1]:text-headline-lg` and so on), in one place, `editor/editorClasses.ts`, with tokens only;
   - ProseMirror's handful of required rules (`white-space: break-spaces` on the root, `.ProseMirror-gapcursor`, `.ProseMirror-hideselection`, `.ProseMirror-selectednode`) in one `@layer components` block in `style.css`, written with `@apply` and theme variables, no hex values.
   - That block is a narrow exception to "Tailwind only, no one-off CSS". It needs your OK; the alternative is to write those rules as arbitrary variants too, which works but is hard to read (the gap cursor's blink is an animation).

## Design

### Protocol (`web/src/sync/protocol.ts`)

- The frame of `Frame.cs`: `[varuint type][varstring pageId][payload]`, written with `lib0`.
- **Sent:** Subscribe 0 (payload: the client's state vector), Unsubscribe 1 (no payload), Update 2, Awareness 4, and Ping 5 (the single byte, no page id).
- **Received:**
  - Update 2 and Awareness 4: one byte array.
  - Sync 3: `[varUint8Array stateVector][varuint count][count × varUint8Array]`.
  - Error 7: a `varstring` code.
  - Pong 6: the single byte.
- An unknown type is ignored, so a newer server does not break an open tab. A frame that does not decode is a broken connection: drop it and reconnect, which resyncs.
- Pin the bytes against the server: a test with frames written out by hand from `Frame.cs` (a Subscribe for a known GUID, a Sync in each mode, an Error).

### The client (`web/src/sync/syncClient.ts`)

The spike's `SyncClient`, with the changes the server now needs. One instance per tab, created when the first page opens and destroyed on logout. It knows nothing of Vue; the store adapts it.

**Pages.** `subscribe(pageId, { readOnly, init })` returns a handle with the document the client made (`init` runs once on it, before the subscribe), its `Awareness`, a state (`syncing`, `synced`, `missing` or `tooLarge`) and a `readOnly` flag, with a callback on change. `unsubscribe(pageId)`.

**Sync** (the invariant: correctness never depends on a single Update frame arriving; every Sync repairs everything):

- Subscribe sends `Y.encodeStateVector(doc)`. The spike sent nothing.
- **Diff mode** (state vector not empty): apply the one update, then send `Y.encodeStateAsUpdate(doc, serverStateVector)` if it is more than an empty update.
- **Log mode** (state vector empty): apply each update in its own `Y.applyUpdate`, never in one transaction and never through `Y.mergeUpdates` (the run 0.5 finding). Replay them into a scratch document for the server's state vector, then send what the page has beyond that. The first update may be a snapshot; Yjs takes it like any other.
- Updates from the server are applied with a private origin, and the client's update handler skips that origin, so nothing is echoed.
- **Until a page's Sync arrives, local edits are held back:** the diff sent after Sync covers them, so nothing is stored twice (scenario 8).
- No server state vector is kept across a reconnect.

**Read-only pages** send no Update, ever, not even the first-paragraph update or a post-Sync diff: the server would answer `read_only` for each. The client still receives and applies.

**Connection.**

- `wss:` or `ws:` to `/api/sync` on the page's own host, `binaryType = 'arraybuffer'`.
- On open: subscribe every page again. The spike's rule stays: every handler first checks that its socket is still the current one, so a late close or message from a socket the client gave up on cannot disturb the one that replaced it.
- **Heartbeat:** Ping every 3 s; any message counts as life; silence for 8 s drops the socket.
  - New: a hidden tab's timers can be throttled to once a minute, and the spike then dropped and reconnected for nothing. When a tick comes much later than 3 s, send a Ping and give it a fresh 8 s instead of dropping. On `visibilitychange` to visible, ping at once.
- **Browser events:** `offline` drops the socket at once; `online` reconnects at once and resets the backoff.
- **Backoff:** 250 ms doubling to 5 s, with jitter (±20%). Reset only after a Sync was answered on the new socket, not on open, so a socket that is refused straight after opening (1008) cannot reconnect at full speed.
- **Close codes:**

  | Code | What the client does |
  | --- | --- |
  | 4401 `session_ended` | No reconnect. The store reloads the sign-in state and the router goes to the login page with a redirect back. |
  | 1001 `server_stopping`, 1006 (no close frame), 1008, 1009, 1011 | Reconnect with backoff and resync. 1011 means the update was neither stored nor relayed: the resync is what saves it. 1008 from our own client is a bug: `console.error` the reason. |

- **Refused at the HTTP upgrade** (401, 403 `origin_invalid`, 429), the browser only sees 1006. After three failures in a row without ever opening, the store reloads the sign-in state: signed out goes to the login page; otherwise keep backing off.

**Error frames.**
- `page_not_found`: the page's state becomes `missing`; the page view shows its not-found message.
- `read_only`: the state becomes `readOnly` and nothing more is sent for that page.
- `too_many_pages`: a translated toast.

**Size limit.** The server closes with 1009 above 2 MiB (`Sync:MaxMessageBytes`); resending the same diff after a reconnect would loop for ever.
- The client never sends a frame over that size. Instead the page's state becomes `tooLarge`: the editor turns read-only, nothing more is sent for it, and the page says the change is too large to save and that reloading discards it.
- One Yjs insert cannot be split, so this is the honest state. The limit is a constant with a comment pointing at `SyncOptions`.
- A paste of more than 2 MiB, or more than 2 MiB typed offline, hits it. Note it in the handoff.

**Leaving a page with unsent edits.**
- Connected and synced: unsubscribe at once. The Update frames before the Unsubscribe are on the same ordered socket.
- Otherwise (offline, or its Sync not answered yet): keep the page subscribed in the background with its document alive. Unsubscribe it after its next Sync, when the diff has gone out.
- While any page has local edits since its last Sync and the client is not live, `beforeunload` asks before closing the tab. Nothing in the browser keeps them across a reload until B.6.

**Awareness**, plumbing only: no presence UI in this run.
- Local changes are sent; remote ones are applied with the private origin and not sent back.
- After every Sync the local state is announced again: the server dropped it with the old connection.
- Unsubscribe and destroy remove the local state.

### Store and status (`web/src/stores/sync.ts`, `web/src/sync/SyncStatus.vue`)

- **The store:**
  - `status`: `connecting`, `live` (socket open and every open page synced) or `offline`;
  - `open(pageId, { readOnly })` returns the handle with a reactive state; `close(pageId)`;
  - destroys the client when the person signs out, and handles session-ended and refused connections as above.
- **The pill:** the design's sync status pill (`rounded-full`, a 6 px dot in `sync-active` or `sync-offline`, `label-xs` text), in the page header. `role="status"`, so a screen reader hears it change.
  - Texts: "Connecting…", "Live", "Offline · changes are kept in this tab".
- **1.11a's page view** opens the page read-only through the store and shows the pill. That is the client's first real use and what its e2e test drives; 1.11b puts the editor on the same handle.

### Editor (1.11b, `web/src/editor/`)

**`PageEditor.vue`**, keyed by page id in `PageView.vue`, so switching pages builds a new one:

1. **Mount:** a new `Y.Doc`, apply the first-paragraph update, `sync.open(pageId, { readOnly })`, then `useEditor` with Collaboration on that doc.
2. **Unmount:** destroy the editor, `sync.close(pageId)`; the doc is destroyed when the client lets the page go (see "Leaving a page").

- **When it can be edited:** once the page's Sync arrived, or at once while the client is offline. Typing into an existing page before its content arrived would land in the first paragraph. Read-only for viewers and in the `readOnly` and `tooLarge` states.
- **Roots:** `role="textbox"`, `aria-multiline="true"` and a translated `aria-label`, through `editorProps.attributes`.
- **`missing`** shows the page view's existing not-found message.

**Extensions** (`extensions.ts`):

- **StarterKit:**
  - `undoRedo: false` (Collaboration brings Yjs undo);
  - headings at levels 1 to 6, so an import loses no level (the design styles three; 4 to 6 look like 3);
  - Link configured as below.
  - Blockquote, horizontal rule, strike, underline, inline code, hard break and the trailing paragraph stay on: the import needs them and they cost nothing. The trailing paragraph can double when two clients open a page that ends in a table at the same moment; that is the 0.3 finding again and harmless.
- **Collaboration** on the `default` fragment (the field the sidecar's text extract reads), with **`enableContentCheck: true`**.
  - The danger it guards against: a tab still running an old bundle after an upgrade (images arrive in 1.14) drops the nodes its schema does not know, and its next edit would delete them from the document.
  - With the check, `onContentError` disables collaboration for that page and shows a translated "this page needs a newer version: reload" message. Data is never lost by a stale tab.
- **TaskList and TaskItem**, nested allowed:
  - the checkbox gets a translated label (`a11y.checkboxLabel`, or the node view's own label if that option is missing in the installed version);
  - in a read-only editor clicking it does nothing.
- **Table, TableRow, TableHeader, TableCell**, `resizable: false`.
  - TipTap's table `renderHTML` writes a `style` attribute (`min-width`) and the column group can too, and a `style` attribute set through `setAttribute` breaks the CSP. Extend the table to render without it.
  - Tables come in by paste in this run; the slash menu (1.12) will insert them.
- **Placeholder** on the empty document, translated, shown with Tailwind's `before:content-[attr(data-placeholder)]`.
- **`injectCSS: false`.**

**The CSP probe comes first:** before any styling, mount every extension in the real app and run the CSP e2e check. Fix each violation by configuration or by overriding a `renderHTML`, never by loosening the policy. Write down what was found. The spike ran with a relaxed policy, so this has never been checked.

**Paste and links** (`sanitize.ts`):

- `transformPastedHTML: (html) => sanitizePastedHtml(html)`, DOMPurify with an allow-list:
  - **Tags:** `p`, `h1`–`h6`, `ul`, `ol`, `li`, `blockquote`, `pre`, `code`, `strong`, `b`, `em`, `i`, `u`, `s`, `del`, `strike`, `a`, `br`, `hr`, `table`, `thead`, `tbody`, `tr`, `th`, `td`, `span`, `div`, and `input` for task items.
  - **Attributes:** `href`, `colspan`, `rowspan`, `start`, `data-type`, `data-checked`, `type`, `checked`, `style`.
  - **Why `style`:** ProseMirror reads it only while parsing, in a detached document, and drops it. Without it, Google Docs' `<b style="font-weight:normal">` wrapper turns a whole paste bold. If keeping it shows up as a CSP violation, drop it and give Bold a parse rule for that wrapper instead.
  - **URIs:** DOMPurify's default safe-URI rule plus the Link check below.
  - Images are not in the schema until 1.14, so `img` goes.
- **Link:** `autolink` and `linkOnPaste` on.
  - Protocols `http`, `https` and `mailto` only; `isAllowedUri` refuses everything else, and the rendered `href` is checked again. That second check is what stops a `javascript:` link that another client put into the Yjs document.
  - `rel="noopener noreferrer nofollow"` and `target="_blank"`.
  - Editing a link's address waits for 1.12's menus; Ctrl+K is the command palette's (B.4).

**Title field** (`web/src/pages/TitleField.vue`):

- A `<textarea>` in `headline-xl` (`headline-xl-mobile` on phones) that grows with the title: Tailwind's `field-sizing-content`, with a CSSOM height fallback for browsers without it, never a `style` attribute in the template.
- A line break typed or pasted becomes a space. Placeholder "Untitled" from `tree.untitled`.
- Saving and read-only rules as in decision 4. Errors through the notifications store with the existing translated codes.

**Styling:** decision 7.
- Body in `body-lg` with a reading column of `max-w-3xl` (the page view's).
- Code blocks: `code-inline` on `surface-subtle`, `rounded` with a hairline `border-subtle`.
- Checked items: `line-through` with 40% opacity.
- Links in `secondary`.
- Tables with `border-subtle` cells.
- Mobile first.

## Tests

**1.11a, Vitest**

- **Protocol (`protocol.test.ts`):** every frame type both ways; the bytes from `Frame.cs`; an unknown type is ignored; a truncated frame throws.

    - an empty client and a client with offline edits both converge, in each mode;
    - edits made before the Sync are sent once, in the diff;

    - nothing is echoed.
  - **Reconnect:**

  - **Heartbeat:**
    - a Ping every 3 s;
    - 8 s of silence drops and reconnects;
    - any message resets the clock;
    - a late tick (a throttled timer) pings instead of dropping.
  - **Browser events:** `offline` drops at once; `online` reconnects without waiting; a late close or message from the old socket changes nothing.
  - **Error frames:** `page_not_found`, `read_only` (no Update after it), `too_many_pages`.
  - **Read-only:** a read-only page with local changes sends no Update.
  - **Size:** an update over the limit is not sent and the page becomes `tooLarge`; no reconnect loop.
  - **Leaving:** leaving while offline keeps the page until the next Sync, then unsubscribes; leaving while live unsubscribes at once.
  - **Awareness:** sent, applied without an echo, announced again after a Sync, removed on unsubscribe.
  - **Other:** frames for a page not subscribed are ignored.
- **Randomised convergence (`convergence.test.ts`)**, the critical-path test for sync. A seeded generator (no new dependency, about 50 seeds, under 10 s):
  - **Each schedule:** three clients on one page, random edits through Yjs (insert, delete, format attributes, emoji), disconnects, silent deaths, reconnects, the hub switching between diff and log mode, frames delayed and held back, a page left while offline.
  - **At the end:** every client and the hub have the same document (Yjs snapshot fingerprint and the text), and every edit ever made is in it.
  - A failing seed prints itself.
- **Store and pill:**
  - one client per tab, created lazily, destroyed on sign-out;
  - session ended goes to the login page with the redirect;
  - the pill shows each state in both languages, with `role="status"`.

#### As built

- **`web/src/sync/`:** `protocol.ts` (frames written and read with `lib0`, the 2 MiB limit), `syncClient.ts` (the client, no Vue), `SyncStatus.vue` (the pill). **`web/src/stores/sync.ts`** adapts the client: `connection`, `pages`, `live`, `display`, `sessionEnded`, `open`, `close`, `destroy`.

- **Dependencies:** `yjs` 13.6.33 and `lib0` 0.2.119 (exact, the versions already in the lockfile) and `y-protocols` 1.0.7. `pnpm why yjs` shows one copy.
- **Tests' stand-ins:** `testing/fakeSyncHub.ts` (real Yjs behind it; diff and log mode, per-socket `dead`, held-back messages, refused sockets, `read_only` and missing pages) and `testing/setup.ts` (a WebSocket that never connects, so a component that opens the socket does not reach for the network in a test).

#### Where it differs from the card

1. **The client makes the document,** not the editor: `subscribe(pageId, { readOnly, init })`, where `init` runs once on a new document, before the subscribe. The card had the editor make the `Y.Doc`. Why: a page left with unsent changes is kept in the background with its document, and opening it again must give the same document back. 1.11b applies the first-paragraph update in `init`.
2. **`readOnly` is a flag on the handle,** not a page state. The states are `syncing`, `synced`, `missing` and `tooLarge`; `readOnly` is true when the caller asked for it or the server answered `read_only`.
3. **Awareness is silent until a caller sets a state.** y-protocols starts every client with an empty state, which the client would have announced to every other socket of the page. The first e2e run showed it (the raw-socket test got an Awareness frame it did not expect).
4. **A page is released only after a pong.** The card's rule was "unsubscribe at once when connected and synced". But a connection that died unnoticed swallows an update the client believes was sent, and leaving the page then threw the document away. The convergence test found it (9 of 50 seeds fail without it). Now every sent update notes the number of the first ping sent after it; leaving a page whose last update is not yet confirmed sends a ping and waits for that pong. Losing the connection turns unconfirmed updates back into unsent ones, which the next sync sends again.
5. **Every ping is counted** (`pingsSent`, `pongsReceived`, reset per socket) for the rule above. The heartbeat itself is as in the card, plus a ping when the tab becomes visible.

#### Found while building

- **A first version of the convergence test failed for three reasons that were not the client's:** it edited documents the client had released, it made dead connections alive again before the client noticed, and it stopped waiting before the heartbeat could notice. The fourth reason was the real bug (point 4).
- **A fake that answers in the same turn as the request hides races.** The hub's answers go through `queueMicrotask`, as a network's do.
- **`browser.newContext()` in Playwright inherits the project's `storageState`:** a "second browser" is signed in as the administrator unless `storageState: SIGNED_OUT` is passed.
- **`getByRole('status')` is now ambiguous on a page:** the pill is a status. The trash test looks for its banner by its words.
